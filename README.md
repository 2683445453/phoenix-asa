## 原生相机及泰克适配（2026-09-17）

自由相机实验在不复制到服务器的本地 Character 上调用 GCM 共用的 `CheatManager.Fly`，不接管或移动真实人物。现场已确认原生 Fly 成功，但普通角色视角被游戏立即重置；新候选改用附着在飞行角色上的 CameraActor，尚待实机验证。鼠标沿用原控制器输入，保留快捷栏、鼠标和交互键。骑乘功能仍未解决翼龙和南方巨兽掏枪。泰克步枪持续伤害已由用户确认；狙击枪仍会在服务器过热。远程客户端保留服务器同步热量，射速调整以服务器扣弹和伤害为准。

新增原地打开原生贡品面板、浮空建筑放置参数、恐爪龙大跳三个实验入口，以及恐爪龙管理员原生飞行／行走按钮。管理员飞行由服务器检查权限，用“恢复原生行走”结束；大跳仍受原生蓄力、耐力及服务器移动校验影响。贡品面板只完成客户端编译，完整界面及实际上传须实机与服务器验证；浮空建筑也未确认通过服务器支撑检查。

已在无加入密码的独立本地专服加载新 DLL。用户操作泰克步枪连续射击期间，同步采样确认服务器热量保持为 0、服务器持续扣弹；伤害持续性和其余实验功能的验证范围见 [功能补充与对照](docs/phoenix-20260917-功能补充.md)。构建与模拟回归记录位于 `release/native-features`，只读现场采样位于 `release/diagnostics/followup-*-monitor`。

## 本地授权验证（2026-09-15）

新增独立的本地授权验证版本：本机服务管理激活码、首次激活起算、单设备绑定、续期、吊销和解绑；启动器与 DLL 独立校验 ES256 签名凭证，并在运行中检查期限。客户端使用 Windows DPAPI 保存会话凭据，测试私钥及数据库只保存在 `.local-license`。

- [本地操作与服务器迁移说明](docs/phoenix-本地授权验证.md)，[自动化测试](tests/run-license-tests.ps1)。正式加壳、签名及服务器部署另行完成。
- 激活前先运行 `./licensing/manage-local.ps1 -Action start` 后台启动本地服务；用 `-Action status` 查询、`-Action stop` 停止。生成卡密不会自动启动服务。

## 自动采集寻路与效率检查（2026-09-14）

- 修复遇阻后的重规划饥饿：原先每 30 ms 把下一次重算设为“当前时间 + 220/350 ms”，持续遇阻时永远到不了执行时间。现在只允许提前已有期限，脱困尝试也立即请求重规划。
- 陆地自动靠近并启用安全／实验导航时，从当前资源缓存中取最近 4 个候选，分别估算可采集站位和行走距离，优先选择已验证能进入采集范围且路径较短的资源；复用选中的路线。单次选择每个候选至多一次同步寻路。缺少客户端导航数据时，通过最多 6 段连续地面／碰撞探测比较短距离直达站位，无法确认的走廊保留距离回退；实际行走继续经过原有避障与落差检查。这是局部候选比较，并非全地图最优路线。
- 只读检查当前运行中的 Ragnarok_WP，`World.NavigationSystem` 为空；因此补强实际使用的局部避障：同一绕行角度比较左右两侧，增加一段前视探测，优先选后续仍可通行的一侧。前方直达路线安全时直接通过，不额外扫描侧面。墙体／地形不会仅因靠近目标资源就被当作可忽略障碍。
- 水下先按当前航向筛选再截取候选，一次遍历缓存即可完成选择，避免密集的身后资源占满候选名额。搜索无结果时最多每 250 ms 重试；通畅且有进展的完整路线每 2800 ms 刷新，遇阻／脱困时提前至 220–350 ms；候选落点投影重复时避免重复同步寻路。
- 普通采集和跨步者共用每 500 ms 的收益采样，按物品类型合并背包数量，堆叠合并、排序、食物减少与物品移出不会当成采集成功；某种物品增加可以独立更新进展。继续取得资源时不再因累计攻击满 10/15/45 秒而强制换点；无收益超时仍会跳过目标。接近目标的超时同样参考最近有效行走进展。
- 换目标时保留上次攻击的待执行间隔；已到期时只保留 60 ms 的转向缓冲，替代每次重置为 250 ms。生物的原生攻击动画、冷却与服务器采集规则不变。
- 新增 `tests/run-harvest-efficiency-tests.ps1`，覆盖连续遇阻时的重规划、生产中与停滞时的超时、可达目标／路径长短比较、无导航回退、换目标冷却、食物消耗与资源增长同时发生，以及绕行一侧后续遇墙／落空时的选择。未自动驾驶运行中的游戏；每分钟实际产量与复杂地形效果仍需游戏内验证。

## 显示可读性、射速一致性与泰克弓实体箭（2026-09-14）

- 活体人物／生物的名称、距离、生命值和眩晕值合并成同一信息面板，配深色背景、细状态条及目标连接线。默认字号 16 像素、最小 13 像素，按当前 DPI 换算；字号、边距、线宽、四角样式、防重叠均可保存。锁定目标和近处生物优先，信息在目标四周就近放置；没有合法空位时整组隐藏，避免文字和数值分离。建筑、资源、掉落物共用字体大小与标签占用区域。
- 修正本地开火特效多于实际扣弹和伤害：远程客户端修改自身 `TimeBetweenShots` 无法同步服务器开火计时，现仅在武器具有本地主机权限时应用射速倍率，远程联机保留原生间隔并显示原因。此项没有实现远程服务器加速；扣弹、伤害、换弹仍由原生流程处理。
- 泰克弓实体射箭模式按当前 `AmmoConfig` 和 `CurrentAmmoTypeIndex` 读取金属／爆炸／麻醉／火焰箭的实际投射物类型；按实际蓄力和弹种读取速度、重力。运行中蓝图核验确认爆炸箭生成后另设初速和最高速为蓄力插值（当前默认 2000–2400），已单独处理。即时命中修正仅在即时模式生效，实体箭由弹道预判路径处理；没有主动调用会发射或造成伤害的弹种选择蓝图。
- `tests/run-gameplay-extensions-tests.ps1` 增加信息面板防重叠、四周与边缘布局、最小字号、主机／客户端射速、四种泰克弓箭速及配置保存检查。当前游戏中的调查仅做只读字段／原生函数／蓝图检查，未自动射击，也未将离线验证当作伤害或显示实测结果。

## 功能与显示位置修正（2026-09-14）

- 修正方框、血条与名称整体落在目标旁边／角落的问题：所有 ESP 世界投影复用魔法子弹的 `AimCanvasSpace`，从视口像素转换为 Canvas 的 ClipX／ClipY 逻辑坐标。屏幕边界判断使用同一坐标系；每帧读取当前模型边界，取消旧边界的位移补偿和文字横向吸附屏幕边缘；投影失败立即丢弃旧矩形。建筑名称以建筑包围盒中心定位。资源、掉落物和水源标记一并修正。
- “战斗与瞄准”提供枪械射速倍率（0.25–10 倍），修改本地主机即时枪械的发射间隔，远程联机保留原生射速。关闭、失焦、打开界面、换角色、换枪、骑乘和卸载时恢复原值，不修改类默认对象。
- “战斗与瞄准 → 投射物自动预判”：依照当前投射物默认速度、重力、弓蓄力、原生发射请求速度和目标移动速度求解最早可用弹道，并逐段检查遮挡。适配原生投射物武器路径（流星锤、复合弓、弩等）；可设置最大飞行时间及额外延迟。没有有效参数或无法拦截时保留原生发射；泰克弓即时命中路径不使用飞行预判。蓝图切换弹种及特殊弹速行为仍需逐模式实测，未主动调用有射击副作用的弹种选择蓝图。
- “辅助与自动化 → 自动吸取附近空投／掉落包”：空投及包可分别筛选，按距离选择一个可访问目标，后台请求同步物品后发送标准批量取出请求；支持范围、请求间隔及负重停止阈值。保留距离、等级和权限检查；空包／未确认转移冷却重试；手动界面和其他取水晶会话优先。单次批量转移可能超过负重阈值，不将请求发出视为取物成功。
- 新选项默认关闭，配置可保存。新增 `tests/run-gameplay-extensions-tests.ps1` 检查移动目标弹道、重力、不可达目标、异常参数、100%–200% DPI 下目标与方框的坐标一致性，以及新配置往返保存。编译及离线检查不能替代游戏实测；当前会话中游戏未运行，显示对齐和服务器效果尚待验证。

## 本地稳定性修复版（2026-09-12）

- 泰克长矛锁定数量可设为 1–5 个（默认 1），从现有锁定圆内按实际距离选择最近的有效单位，分别显示名称、距离和连线，当前招架对象会标注。每个目标独立记录打击时机，按预计打击时间排队，同一时间的打击优先较近目标；过期或失效攻击丢弃。新增“自动正对攻击者，招架后回正”（默认开启），使用实际控制朝向，保留期间的鼠标转向；招架结束、手动操作、暂停、换武器和卸载均恢复朝向。转向期间固定锁定组并继续移除失效目标，避免视角变化误换锁。魔术子弹的出射方向修改不等同于格挡方向，因此本版未宣称无转镜头格挡；完全同时来自不同方向的攻击不保证全部抵挡。多目标与转向回正已补回归测试，实际游戏效果待验证。
- 泰克长矛近战招架距离上限提高到 25 米，菜单及运行时共用上限并可保存。飞行物检测补齐物理速度、连续位置采样、同步速度及原生历史速度，不再仅因 MovementComp 为空或速度为零漏掉弹体；检测独立于近战目标、朝向和武器是否就绪。投石使用实际碰撞范围，撞击爆炸的毒液等弹体纳入原生范围伤害半径；已爆炸或不再允许继续飞行的命中弹体被排除，可继续飞行的反弹／穿透弹仍参与检测。以发射者判定友方，避免本地复制代理的所有权遮蔽敌方攻击。菜单与中央提示分别显示识别、移动、预计接近和遮挡状态。已只读核对当前加载的 `ProjDilo_C → PrimalProjectileDilo → ShooterProjectile`，本次采样未捕获正在飞行的弹体，也未加载金刚投石类；这些具体攻击的挥矛效果仍需实机验证。

### 2026-09-21 泵动霰弹枪双端验证（进行中）

本机独立专用服测试，客户端为非 authority。关闭两套换弹功能时，双端弹夹记录为 6→5→4→3→6。开启秒换弹、重发间隔 500ms、旧霰弹枪自动换弹关闭后，用户未按 R，服务器连续三次记录 6→5→6；从扣弹到补满分别约 0.633 / 0.622 / 0.621 秒（采样周期 50ms）。客户端两项换弹时长均为 0，服务器仍为 NoAnimReloadDuration=0.2、ReloadDurationPerAmmoCount=0.5，CurrentAmmo 为 37→34。

结论：此场景已确认服务器接受自动换弹，尚未证明服务器零时长换弹或相对原生流程提速。基线没有记录按 R 时刻，不能拿“最后一枪到补满”直接比较换弹耗时。120/2000ms、单机 authority、无弹药、弓、泰克榴弹发射器与卸载恢复仍待验证。

记录：`release/diagnostics/instant-reload-review-20260921/shotgun-500ms-result.json` 及同目录双端 `reload-samples*.jsonl`。

关闭开关恢复已实测通过：同一客户端武器的 NoAnimReloadDuration 从 0 恢复为 0.2，ReloadDurationPerAmmoCount 从 0 恢复为 0.5，两项补丁 Owner 已清空；弹夹仍为 6。该结论只覆盖关闭开关，不代表卸载恢复已验证。

120ms 间隔对照：服务器扣弹到补满为 [0.625, 0.625, 0.624, 0.674, 0.624, 0.676, 0.622, 0.673, 0.623, 0.672, 0.625, 0.569] 秒（50ms 采样），服务器换弹字段仍为 0.2/0.5。用户反馈仍自动装填；代码条件为弹夹小于容量即发送 ServerStartReload，故每打一发就触发补弹。旧自动换弹开关已关闭，行为来自新秒换弹功能；请求间隔不是装填时长。
