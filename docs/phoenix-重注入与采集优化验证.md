## 崩溃证据与修正

核对了 `09.16-20.55.05.crashstack` 及同进程的 DLL 初始化日志。重新注入于 20:55:03 完成初始化，随后游戏报告 `0x00008000` 异常；栈没有直接定位到 phoenix。不能将本次崩溃唯一归因于残留，但代码中确实存在需要修复的卸载隐患。

1. 虚表副本曾借用游戏模块的数据区，并在卸载时清零。现在改为独立分配，解绑时核对所有权并恢复原生函数指针。
2. 已发布虚表副本解绑后保留到进程退出，避免已经读取旧表地址的线程访问释放后的内存。保留表不含本 DLL 的回调；这是一项有意的少量内存保留。
3. 先等待初始化线程和游戏线程恢复确认，再停止挂钩、排空回调、结束后台线程、检查线程引用与 GPU 完成状态。无法确认解绑时保留 DLL，并写入阶段日志。
4. 初始化和卸载使用统一停止状态。必要的三个 D3D12 挂钩创建、启用失败时记录错误并协调回滚；初始化等待可响应停止请求，临时设备创建尝试设为 30 秒上限。
5. WndProc 按窗口保留原过程，旧窗口延迟消息不会误转发给新窗口。最终解绑依据实际挂钩窗口；其他组件占用窗口过程时停止卸载。
6. 骑乘采集移至串行的本地相机回调，并在相机挂钩不可用时由 PostRender 接替；恢复参数与运行更新使用同一把锁。卸载时确认释放所持输入和跨步者光束请求。

线程 RIP／寄存器检查和本次循环测试不能证明任意第三方长期保存的旧回调地址已消失。没有在 ASA 中执行本次注入或卸载，也没有声称游戏闪退已通过实机复测。

## 启动展示

启动展示不再依赖 Canvas 首次回调，只累计游戏前台可见帧；菜单打开也显示，且绘制在菜单上方。凤形线条逐步展开，配合毛玻璃卡片淡入淡出。“设置 → 界面偏好 → 重播启动动画”可临时重播，不改变保存的自动展示偏好。

离线渲染确认了修复前的菜单遮挡，并验证修复后的图形、文字和关闭按钮完整可见。

## 采集与参数

采集页顺序为主开关和状态、资源目标、采集方式、移动与避障、背包清理。普通坐骑与跨步者参数分开；关闭对应功能时参数收起，说明通过悬停显示，自动丢弃仍可独立使用。

| 参数 | 范围 |
| --- | --- |
| 搜索已加载资源 | 5–300 米 |
| 普通坐骑期望停靠距离 | 1.5–30 米 |
| 跨步者寻路／开始采集距离 | 10–150 米 |
| 普通攻击间隔 | 200–10000 毫秒 |
| 安全导航允许落差 | 0.5–15 米 |
| 普通坐骑本地近战半径倍率 | 1–5 倍，默认关闭 |

路线比较分批执行，每次更新比较一个候选；已选路线每次刷新最多调用两次同步导航。保留有效路线，空目标时降低搜索频率，缓存路径剩余长度、坐骑几何及已验证的攻击范围。移动前继续检查地面、落差与碰撞。普通坐骑和跨步者持续没有收益时逐步靠近；长攻击间隔相应延长观察窗口。

普通龙实验选项只处理当前坐骑可验证的基础近战 `MeleeSwingRadius`，单项调整不超过 20 米，原生值更大时不缩小。排除投射物与跨步者，关闭或暂停时条件恢复，并保留其他来源的修改。可自定义快捷键，快捷停止会关闭该选项。生物蓝图、模组和服务器可能忽略本地修改，不能保证服务器认可扩大后的命中与采集范围。

## 实机复测建议

1. 完整退出旧游戏进程后使用新版；注入完成后切回游戏观察启动展示，或在界面偏好中重播。
2. 先以默认参数、少量目标资源验证普通坐骑采集，再逐项调整搜索和停靠距离。将复杂地形、无导航数据与跨步者分别验证。
3. 单独开启普通龙实验范围，检查是否有实际资源收益；关闭、下坐骑和切换生物后检查恢复。
4. 保存配置后卸载，核对同目录 `logs` 下 DLL 日志是否出现 `Unload complete`；出现 `blocked` 或 `postponed` 时按日志处理，不叠加注入。发生异常时保留对应游戏 crashstack 和 DLL 日志。
