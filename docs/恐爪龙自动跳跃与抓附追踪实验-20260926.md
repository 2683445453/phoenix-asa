# 恐爪龙自动跳跃与抓附追踪实验

## 本版范围

把两个实验放进同一包，分组运行：无目标空中自动跳跃请求，以及原有无目标抓附的脱离追踪。默认都关闭。此前普通跳跃、长按滑翔、反复按空格的 A/B/C 基线已经完成，无需重做。

自动跳跃只提交 `ServerRequestLatchedAutoJump(Velocity)`，不调用本地 LaunchCharacter、不写运动速度、不伪造地面，也不先进入抓附。方向取视角水平朝向；水平/向上分别设置，默认 15/4 m/s。该参数是目标速度向量，不是给当前速度追加的增量。每次 F6 按下沿最多一次，冷却 3 秒；长按不连续，条件不满足的按键不延迟补发。客户端须为当前骑乘恐爪龙、Falling、抓附状态 0，且没有未完成跳跃请求或明显非零缓存。函数、参数布局、速度范围和日志写入全部通过后才提交。

服务器保留原生请求处理、耐力、动画、碰撞和网络纠正。静态代码发现这条入口没有普通抓附跳跃的速度阈值，但是否在无目标空中接受，仍需本次实测。本版不宣称已经实现稳定悬停，也不持续延长近零重力阶段。

抓附仍使用原来的客户端 CanContinueUberpounce 补丁和最多每 250 ms 的续抓。它仅覆盖客户端的一项检查，不能保证服务器持续认可；服务器表面检查、其他结束路径或动画事件仍可能结束状态。当前尚不能断定用户每次自动脱离具体由哪条路径触发。本轮以双端时序区别“游戏结束”和“本功能主动取消/续抓”。抓附组的空格仍保留旧版手动 LatchedJump 和延迟一次本地 LaunchCharacter，日志明确标记该回退；其效果不能算成新自动跳跃入口生效。

## 更新与准备

1. 完全退出 ARK 客户端，保留本地测试服务器运行。
2. 使用 `D:\Programs\Begeerte-ASA-main\dist\phoenix\phoenix.exe` 启动/加载新版。游戏占用旧 DLL 时，构建生成 `phoenix.dll.pending`，启动器在游戏完全退出后应用。
3. 回到原本地服；必要时控制台执行 `open 127.0.0.1:7797`。骑上原恐爪龙。
4. 在移动功能区域关闭旧的恐爪龙大跳、空中限速、恐龙移速、原生坐骑跳跃/悬停，以及旧滑翔诊断记录。不要将 F6 绑定到菜单或其他快捷功能。
5. 每轮找可留空数秒、前方无障碍的位置。菜单只在设置和结束后打开；实验按键全部在关闭菜单、游戏有焦点时操作。

## 第一组：空中自动跳跃

1. 关闭无目标抓附和抓附脱离追踪，只开启 **恐爪龙空中自动跳跃请求（实验）**。
2. 使用默认水平 **15 m/s**、向上 **4 m/s**。
3. 关闭菜单，正常起跳或从边缘进入空中。松开空格与方向键，保持视角朝前；离地后轻按并松开 **F6 一次**。
4. 观察是否播放起跳动作、前冲、向上抬升，及随后是否回拉。不要连续按键掩盖单次结果。
5. 等几秒或落地后打开菜单；记录自动保存。查看“已提交一次请求”还是具体拒绝原因。这里“已提交”不等于服务器接受。
6. 如需验证纯水平请求：关闭实验开关，等待约 1 秒，再开启；向上速度改为 **0**，其余不变，重复一次。0 表示传入向上分量为零，不代表锁定高度或保留原垂直速度。

## 第二组：抓附为何自行结束

1. 关闭自动跳跃和所有诊断开关，等约 1 秒。然后只开启 **恐爪龙无目标空中抓附（实验）** 和 **恐爪龙抓附脱离追踪**。
2. 关闭菜单、起跳、松开空格；空中轻按 **F6 一次**启动续抓。
3. **约 3 秒不按空格、不连按 F6、不输入方向**，观察是持续抓附、抖动续抓还是直接下落。
4. 轻按 **F6 一次**主动取消。稍等后打开菜单，保存本轮记录。
5. 关闭“抓附脱离追踪”，等待约 1 秒，再开启；重新起跳，F6 启动续抓，等待约 1 秒，再轻按 **空格一次**。观察是否只解除、前冲/抬升、随后回拉。结束后打开菜单保存。
6. 测完关闭两个开关。无需为了记录状态同时打开菜单按 F6。

每次最多记录 120 秒；打开菜单、失焦、下骑、对象改变或冲突会结束记录。结束后须把记录/实验开关关闭再开启，才开始下一轮；只改速度不会自动重开记录。新自动跳跃与抓附追踪互斥，出现冲突提示时先关闭各实验，再按步骤选一组。

## 日志及判定

客户端日志：`dist/phoenix/logs/deino-glide-*.csv`，文件头 `mode=2` 为自动跳跃、`mode=3` 为抓附追踪，`mode=1` 为旧滑翔记录。保留原文件前缀以兼容分析工具。采样至少间隔 50 ms，包含输入、位置/速度、抓附状态、缓存/实际抓附跳跃速度、重力、插值速度与服务器时间字段的客户端副本。`nan` 为无法读取，不能按零解释。

`# request` 是本功能准备发送的向量；`# event` 的 `own_...` 是本功能自身操作，其他名字是现有 ProcessEvent Hook 观察到的函数，第四列 0/1 表示入口/返回。CanContinue 的返回值只在返回后读取。动画通知名在游戏线程解析；Hook 中不查名称、不调用 UE、不写文件。256 条有界队列溢出记录 `dropped_events`，不会无限积压。

Hook 只能观察经过它的调用，蓝图内部直接调用可能绕过 ProcessEvent。因此没有 End 或通知记录不能证明没有执行；`process_event_hook=0` 表示该 Hook 不可用。服务器采样同样可能漏掉短于采样间隔的瞬态，必须结合持续的时间字段、状态和位移，不能只看一帧缓存。

服务器只读脚本：`release/diagnostics/monitor_deino_actions.py`，本地服的记录目录为 `release/diagnostics/deino-action-server/`。每 50 ms 读取当前同一恐爪龙的位置/速度、抓附状态、Cached/Latched 速度、重力、请求/起跳时间和骑手。文件 `sampler-session.json` 标识采样进程、对象索引/序号、日志路径、时限；对象身份改变立即停止。服务端属性没有反射时保存 null，不猜偏移写值。采样使用查询/读进程权限，不调用游戏函数或写服务器内存。默认一小时后自动结束。

重点判断：服务器 LastTimeQueuedAutoJump/LastTimeStartedLatchedJump 是否变化，是否出现缓存→动画重力变化→LatchedJumpVelocity→实际速度的链条；抓附结束是否早于 own_f6_cancel/own_space_pressed，续抓是否只是周期性重建状态。服务器采样没有执行栈，不能单凭状态变成 0 指定某条表面判定为唯一原因。

反馈按组写“是否前冲、是否抬升、是否回拉、抓附是否抖动、菜单提交/拒绝提示”即可；日志可由开发侧直接读取。

## 实现与验证

- `DeinoGlideProbe.inl`：共用采样、模式校验、单次自动跳跃请求。
- `DeinoActionRules.h`：按键边沿/冷却、模式互斥、速度约束、有界队列；`tests/feature_expansion.cpp` 覆盖规则及配置保存/停止。
- `DeinoActionTrace.inl`、`hooks.cpp`：复用既有 ProcessEvent Hook 的只读观察，弱对象由游戏线程验证。
- `DeinoAirLatch.inl`：加入本功能进入、续抓、取消、空格及旧回退的事件标记。
- 编译、离线测试、语言包/压缩包一致性检查完成后交付；真实游戏效果由用户操作本地服验证。
