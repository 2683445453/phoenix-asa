# 恐爪龙零起点与距离扩展实验（2026-09-26）

本包同时包含 [历史跳跃缓存误拦截修复](恐爪龙点扑跃旧缓存误拦截修复-20260926.md)。零起点是独立、默认关闭的实验选项，实际飞扑成功率和回拉效果待游戏验证。

## 服务器代码依据

已重新只读解析运行中的本地服务器 PID 31260，校验 ExecuteUbergraph 字节码与快照一致。ServerRequestUberpounce 的 0x1426–0x1500 分支实际接受条件是：

```
NearlyEqual(UberpounceStartLocation, ZeroVector, 1e-6)
OR Distance(ServerLocation, UberpounceStartLocation) < UberpounceHackDistCheck
```

`ServerSetUberpounceStartLoc` 直接记录请求参数。本地测试服偏差门槛为 120 cm。因此，客户端先发送零起点，再提交目标，可以测试现有的零向量分支，无需给服务器装插件或改服务器进程代码。这里只确认了该蓝图条件；不把它等同于已验证的请求成功或全部同步问题已解决。

后续仍有携带状态、目标范围、路径碰撞、耐力等检查。目标范围按服务器自身位置计算，门槛为 `GetUberpounceMaxRange()*1.1`，当前参数 3500 cm 对应严格小于约 38.5 m。客户端菜单扩为 10–35 m，默认仍为 30 m，计算时还受客户端读取的原生 MaxRange 限制。存在位置不同步时，客户端计划 35 m 仍可能落到服务器范围之外；本版不能保证任意距离请求都被接受。

只读解析产物：`release/diagnostics/deino-zero-start-gates-20260926/server-gates.json`、`server-gates.txt`。

## 实现与日志

- 新选项“飞扑零起点（实验）”位于空中点扑跃距离下方，默认关闭，支持保存配置；停止自动化时一起关闭。
- 关闭时发送真实当前位置；开启时只把起点 RPC 参数设为零向量，目标仍按当前真实位置与视线计算。
- 每次 `point_dispatch` 同时记录 `actual_start`、`sent_start` 和 `zero_start`，避免把零起点误当成角色传送到世界原点。
- 保留服务器动画启动路径、F6 无固定冷却、反馈等待与状态检查，不自动重发。

## 完整操作步骤

1. 完全退出游戏，运行 `dist/phoenix/phoenix.exe` 更新加载，再进入原本地测试服并骑上恐爪龙。
2. 开启空中点扑跃，距离先保持 **30 m**。可保持大跳 **3.8 倍**；关闭其他运动实验。
3. 第一组关闭“飞扑零起点”，离地后朝开阔空处轻按 F6，等反馈结束后再按，共约 5 次。打开菜单结束记录。
4. 关闭再开启空中点扑跃，打开“飞扑零起点”，仍用 **30 m**，重复约 5 次并结束记录。对照前扑次数、等待超时、回拉现象。
5. 若第二组可前扑，重新开启记录，将距离调至 **35 m** 再试约 5 次。先保持单次按键，不同时改变其他参数。
6. 告诉我三组结果和具体状态提示。服务器只读采样将核对起点值、排队目标、实际位移和拒绝反馈。

离线规则/配置回归和构建结果与本包一起记录；游戏中的成功率仍待用户实测。
