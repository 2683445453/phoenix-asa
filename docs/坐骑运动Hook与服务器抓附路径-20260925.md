# 坐骑运动 Hook 与服务器抓附路径（2026-09-25）

## 本次交付

用户反馈此前 LaunchCharacter / AddImpulse 客户端尝试仍会回拉，要求同时尝试 Hook 和服务器反汇编。本次新增默认关闭的客户端运动 Hook 入口；服务器只读取和反汇编，没有加载插件、模组或修改服务端内存。没有进行自动游戏操作。

### 游戏内操作

1. 完全退出游戏，用 `dist/phoenix/phoenix.exe` 加载本次 DLL，进入原来的本地测试服。
2. 骑恐爪龙或穴角兔，在原生坐骑跳跃设置下开启“原生坐骑跳跃（客户端尝试）”和“运动Hook直接写入速度（尝试）”。
3. 关闭菜单，轻按 F6。地面设置垂直速度，空中沿水平视角追加速度且保留执行时的垂直速度。Hook 选项优先于 LaunchCharacter / AddImpulse 的选择。
4. 菜单状态会区分排队、执行成功、超时/取消、Hook 未安装。“写入一次速度”仅代表客户端执行，不代表服务器接受。松键悬停仍使用上一版实现，没有因本次 Hook 改动而获得新的服务器权限。

### 实现与生命周期

- 复用项目现有 `hkPhysicsRotation` 和原有安装状态；保留原函数调用，在其返回后消费当前坐骑的一次速度请求。不是新安装一个猜测地址的 Hook，也不是运动帧末尾或网络发送后回调。
- 主游戏 Tick 记录按键边沿和弱对象身份；回调仅在同一游戏线程、同一控制器仍骑同一坐骑、运动模式未变、菜单/输入可用、前台且未死亡时消费。恐爪龙抓附/扑击状态再次核对。
- 请求最长等待 200ms，先清除请求再执行，避免重复子步或重入叠加；地面经已校验的 SetMovementMode 切到 Falling，然后写 Velocity。空中使用回调当时的 Velocity 重新计算，不把排队时旧 Z 速度写回。
- 关闭主功能、暂停、下骑、切换对象或卸载清除请求。已经发生的一次速度脉冲不倒放。该选项只是入口选择，持久化但默认关闭；停止自动化关闭原生跳跃和悬停主开关。
- 客户端仍可能在后续运动计算或服务器纠正中失去速度；没有屏蔽纠正消息或改写移动网络包。本版尚未得到用户游戏内结果。

### 恐爪龙蓝图事件定位

对前次本地服字节码快照进行入口及引用扫描，证据为 `blueprint-entry-references.json`。这部分不是完整控制流反编译；窗口内相邻事件的引用不能直接归属于同一条执行路径。

- ServerUpdateTransformDuringLatchedJump 入口 0x1b4b：开头是 EnableServerUpdateTransformDuringLatchedJump 的条件退出；随后包含 ServerUpdateTransformDuringLatchedJumpValidation。附近有 Walking、Recently Unlatched、VectorDistance、BPFastTrace、LastServerTransformCorrectionTime、SetActorLocationAndRotation 和 SetMovementMode 引用。
- ServerRequestLatchedJump 入口 0x207a：包含速度向量长度、比较结果和 CheckForFallingLatchFn 引用，不能把事件名解释成无条件施加任意跳跃速度。
- ServerRequestLatchedAutoJump 入口 0x20e9：首指令直接跳到 0x194c，必须沿跳转目标继续还原；后方线性窗口内容不代表其真实执行链。
- ServerStartUberpounceFromFalling 入口 0x219d：附近有抓附变换、当前位置差和向量长度计算。

## 结果提示修复

用户指出无法打开菜单同时按 F6。检查发现打开菜单确实会暂停功能，而且原先的状态提示被“等待骑乘并关闭菜单”覆盖，导致无法事后读取执行结果；此前要求通过该提示反馈的操作说明不完整。

本次将最近一次 F6 请求结果单独保存，打开菜单、失焦或停止功能时仍可查看，直到下一次请求或重新加载 DLL。若打开菜单时请求尚在排队，会保留“超时或取消”，不会留下已经失效的“等待 Hook”。不在菜单打开时执行速度修改。

同时修复 PhysicsRotationOK 的标记：原来的通用安装函数只检查 MH_CreateHook，而没有核对 MH_EnableHook 的返回值；本入口现在要求两步都成功，启用失败则移除该 Hook。尚未证明本次无效是由该问题造成。

新版操作为：关闭菜单 → 轻按 F6 → 稍后打开菜单 → 查看保留的上一条请求结果。该修复改善诊断，不代表跳跃效果已修复。

提示修复版 Release 编译、启动器自检和语言/归档一致性检查通过。DLL SHA256 更新为 `7a7891706f7566b9b7d50843781e9deea588846cadd5370d1d1ceec540231baa`；前面的哈希是首次 Hook 版历史记录。

## 真实 Hook 入口纠错

用户截图显示“运动Hook请求超时或取消，未追加速度”。该结果只能确认没有完成速度写入，不能证明服务器回拉，也不能单独区分回调没到和前置检查拒绝。

进一步只读核对发现：项目原有 `PhysicsRotation` 名称下的特征码实际匹配客户端 RVA `0x4129960`，位于 CharacterMovementComponent 虚表槽 318。相同服务端槽通过精确符号映射为 `UCharacterMovementComponent.ApplyVelocityBraking(float,float,float)`（服务端 RVA `0x30c8f60`）。客户端函数也读取 xmm1、xmm2、xmm3，与制动的三个浮点参数一致；原 detour 仅接收一个 float，不仅入口命名错误，参数转发也不完整。此前直接复用该 Hook 的验证不充分。

真实 PhysicsRotation 位于槽 289：服务端 `0x30f47f0`，客户端 `0x4134580`。客户端反汇编的旋转标记、CharacterOwner/Controller 检查、有效数据虚调用和 UpdatedComponent 旋转读取，与服务端对应函数一致。两端地址不能互用。

修复内容：

- 将 PhysicsRotation 槽更正为 289，使用当前客户端真实函数的特征码；离线扫描当前客户端可执行文件只有一个匹配，RVA 为 `0x4134580`。
- 安装时必须同时通过特征码唯一匹配、CharacterMovementComponent CDO 槽位一致、可执行地址校验，以及 MinHook 创建/启用成功。旧的制动入口不再挂接，要求退出游戏后重新加载，不能继续沿用旧进程中的 Hook。
- 区分“200毫秒内未收到当前坐骑的同线程运动回调”“因暂停或骑乘状态变化取消”“选项已关闭”“回调已到达但状态检查未通过”。结果仍保留供事后查看。
- 该修改修复确定的 Hook 入口和签名错误；是否能得到服务器认可的速度仍需游戏内反馈，不能把入口修复称为联机跳跃已成功。

证据目录：`release/diagnostics/mount-hook-entry-review/`。`client-entry.json` 保存旧入口匹配和客户端槽表，`server-slots.json` 保存服务端槽位/符号对应。尝试从旧实例快照读取当前骑乘对象没有找到有效对象，因此没有把当前坐骑的回调触发情况列为已验证。

入口修复版已通过 Release 编译、启动器自检、功能回归及生产补丁测试；语言/归档校验为 915 键、712 源码文本。最新 DLL SHA256 为 `ae8d808e364fd94cffb27478dc56ec95ebf7347ac42c72025b6baeeafae38e73`。需要游戏内确认修正后的回调是否实际到达，以及速度是否保留。
