# 本地服务器移动纠正反汇编

2026-09-25。用户反馈原生坐骑跳跃/悬停仍会回拉，授权直接检查服务器代码。本轮仅对本地测试服做只读反汇编、符号匹配和实例读取，没有修改客户端/服务器程序、配置、校验位或网络消息，也未部署插件/模组。

## 结论

当前实现改变了客户端的速度或运动模式，但没有让服务器执行相同的动作。当前恐爪龙、穴角兔实例的服务器原生纠正检查均开启。服务器既比较位置误差，也比较网络运动模式，随后把权威位置、速度和模式发回客户端。这是目前回拉现象的具体代码解释；没有对用户刚才的某次跳跃做动态调用追踪，不能声称已经捕获该次纠正事件。

## 原生处理链

```text
UPrimalCharacterMovement::ServerMove_PerformMovement
  → UCharacterMovementComponent::ServerMove_PerformMovement
  → MoveAutonomous → PerformMovement（服务器计算）
  → ServerMoveHandleClientError
      → UPrimalCharacterMovement::ServerCheckClientError
      → UPrimalCharacterMovement::ServerExceedsAllowablePositionError
      → 保存 FClientAdjustment 的 NewLoc / NewVel / MovementMode
  → SendClientAdjustment → ServerSendMoveResponse
  → ACharacter::ClientMoveResponsePacked
```

- ServerMove_PerformMovement：原生ARK入口RVA 0x5112b10，0x5112cd0调用UE基础实现0x3102430。基础实现0x31028a3通过虚表0xb68调用MoveAutonomous，随后0x31028f7通过0xb48进入误差处理。当前实例的虚表分别解析到0x510d530和0x3100650。
- MoveAutonomous的ARK覆盖0x510d530先处理DeltaTime，再跳到基础0x30eb9f0；它不是把任意客户端Launch调用变成服务器Launch调用的入口。
- ServerMoveHandleClientError（0x3100650）在0x310156e调用虚表0xb50检查误差；失败分支0x3101790把服务器Velocity写入PendingAdjustment.NewVel，随后记录服务器位置、时间戳，bAckGoodMove=false和打包的MovementMode。
- SendClientAdjustment（0x30fe2e0）依据确认/纠正间隔发送PendingAdjustment；0x30fe3df调用ServerSendMoveResponse。
- ServerSendMoveResponse（0x3102970）序列化回复，在0x3102ada调用ACharacter::ClientMoveResponsePacked。不能仅监控旧的ClientAdjustPosition RPC就认为没有纠正消息。

## 为什么悬停也会回拉

UPrimalCharacterMovement::ServerExceedsAllowablePositionError（0x5112620）：

1. 先读取EnableServerMovementCorrections。
2. 在0x5112670调用PackNetworkMovementMode；0x5112676比较服务器打包模式和客户端上报模式。
3. 模式不同则标记纠正分支；不要求先积累明显位置误差。
4. 模式相同仍有位置差平方、移动状态、角色类型、移动基座等条件。

因此客户端把Falling切成Flying，服务器仍按Falling处理时，即使一时看上去悬住，也不代表服务器接受了悬停。

本次两只实际生物读取值相同：

| 服务器字段 | 恐爪龙 | 穴角兔 |
| --- | --- | --- |
| bServerCorrectForMovementModeChanges | true | true |
| bIgnoreClientMovementErrorChecksAndCorrection | false | false |
| bServerAcceptClientAuthoritativePosition | false | false |
| PlayerClientPositionErrorToleranceOverride | 0 | 0 |
| DinoClientPositionErrorToleranceStopped | 3600 | 3600 |
| DinoClientPositionErrorToleranceMovingFlying | 122500 | 122500 |

全局EnableServerMovementCorrections实际为1。容差字段在相关分支与距离平方比较，不应将3600/122500直接读作米；这不是固定允许移动范围，模式不一致可以独立触发纠正。NetworkLargeClientCorrectionDistance=15是区分大纠正的字段，也不是唯一位置容差。

上述控制由服务器进程读取。修改客户端同名字段或屏蔽本地纠正，不会改变服务器所在的位置和规则。

## 为什么Launch / AddImpulse不等于联网动作

UCharacterMovementComponent::Launch（0x30e9840）将向量写入本对象PendingLaunchVelocity。HandlePendingLaunch（基础0x30e7190，ARK覆盖0x510b810）将其应用到本对象Velocity并处理Falling状态、清空待处理向量。这里没有把客户端任意Launch自动发送为服务器跳跃的通用RPC。

AddImpulse有自己的强度/垂直冲量限制，并将冲量纳入本对象运动计算。ARK覆盖还支持CharMoveCompOwnerInterface；它不是“客户端施加了冲量，服务器就必须照抄”的保证。

额外发现：APrimalCharacter::LaunchCharacter（0x4bd5d90）存在GIsOfficialServer条件分支；输入向量长度平方达到225000000时，缩放到长度3000后交给ACharacter::LaunchCharacter。本地服务器实际GIsOfficialServer=0，所以该分支未开启，不能拿它解释本次本地回拉。也不能据此声称所有官服跳跃都被同一限制覆盖：蓝图直接写速度、其他技能入口与此函数不是同一条路径。

## 排除一个名称误导的入口

AShooterCharacter::ServerPrepareMountedDinoForLaunch_Implementation（0x4cf9b00）取两个弱引用之一，然后调用BPPrepareForLaunchFromShoulder。它实际属于肩宠发射流程，不能因为名字含MountedDino就当作正在骑乘的恐爪龙/穴角兔通用跳跃接口。

## 下一步方向与边界

继续客户端开发时，应审查原生技能的服务器处理：哪些真实动作会在服务器上改变速度/模式、需要哪些状态、如何反馈给客户端。恐爪龙抓附/脱离/扑击和兔子原生跳跃都需按各自流程核查，不能靠函数名类比。普通ServerRequestJump的地面/速度/时间检查和穴角兔Alpha重算结论仍成立。

本轮没有发现已经验证可用的纯客户端悬停/空中加速入口，也没有证明所有其他路径都不可行。不再将本地速度修改成功等同于联网成功。
