## 验证边界

新增回归覆盖菜单正反动作识别、补给筛选、雷达朝向和边界、配置往返、旧配置默认关闭、异常数值与停止行为。界面使用真实 ImGui 离线渲染；原生接口以 Release x64 编译检查。

本轮已启动独立本地专服并加载新 DLL。用户手动测试期间，只读同步采样记录了泰克步枪客户端及服务器的热量、弹药、开火时间和间隔。20:20–20:22 的采样已超过 500 发服务器弹夹扣弹，服务器热量始终为 0；用户随后确认步枪持续有伤害。未记录逐发目标血量。离线测试不能证明服务器接受操作、实际命中率或游戏帧率。

后续现场反馈与采样：用户确认原生传服列表能打开；恐爪龙大跳 3.5 倍时客户端起跳参数为 10500，服务器记录到约 4612 cm/s 向上速度及同步轨迹。自由相机可进入／退出，两次现场测试均未解决移动转向；其增强输入映射为空，且 PlayerInput 晚于相机入口创建。上一候选曾补充延迟初始化检查；现已由下述本地 Character 路径替换。狙击枪实测服务器热量仍上升，本地间隔为 2 秒时服务器配置仍为 6 秒；狙击枪不过热尚未解决。浮空建筑、护甲冷却仍未验证。

最新候选已按用户要求替换自由相机路径：只读确认 GCM 的 `Buff_CreativeModeHelper_C` 在双击跳跃后调用 `ServerSetFlight`，执行 `fly / walk`。用户要求人物保持原位，因此在不复制的本地 Character 上直接调用相同的 `CheatManager.Fly`，使用原生 CharacterMovement 飞行；原人物控制器保持原 Pawn。现场已读到 Fly 成功、移动模式为 Flying，但视角随即被游戏重置，用户确认仍无法使用。进一步只读核对 `ShooterPlayerCameraManager::UpdateViewTarget`，该路径会把非 CameraActor 的替代目标切回原 Pawn。新候选改为给飞行 Character 附着原生 CameraActor，并以它作为视角目标；临时控制器通过原生生命周期计时清理，因为其 K2_DestroyActor 实现为空。新候选尚未实机验证。

人物移动输入由一个可恢复的忽略计数隔离，鼠标仍走原控制器；快捷栏、鼠标按键和交互键不额外拦截，菜单／背包／聊天期间只暂停视角移动。关闭、失焦、死亡、骑乘或世界变化时恢复视角与输入并释放本地对象。相机目标规则、附着失败回滚及控制器计时清理已加入生产代码模拟回归；模拟通过不等于真实游戏已通过。

骑乘现场反馈仍为翼龙与南方巨兽无法掏枪。专服只读采样显示，这两种坐骑的实例及类默认对象均未开启 bAllowMountedWeaponry / bAllowMountedWeaponryPVE；客户端本地覆盖不能据此视为服务器接受。尚未定位完整装备拒绝链，也未修改专服坐骑权限。

骑乘最新修正：装备前处理人物 `bPreventAllWeapons`；持枪第三人称补上原生相机实际检查的 `bForceTPV_EquippedWhileRiding`，并处理换枪重新覆盖视角。保留原生装备、开火和停火输入；增加人物装备、坐骑装备前／开火判断的诊断结果。翼龙掏枪、服务器装备接受和骑乘伤害尚未验证，不能标为已修复。

### 2026-09-21 泵动霰弹枪双端验证（进行中）

本机独立专用服测试，客户端为非 authority。关闭两套换弹功能时，双端弹夹记录为 6→5→4→3→6。开启秒换弹、重发间隔 500ms、旧霰弹枪自动换弹关闭后，用户未按 R，服务器连续三次记录 6→5→6；从扣弹到补满分别约 0.633 / 0.622 / 0.621 秒（采样周期 50ms）。客户端两项换弹时长均为 0，服务器仍为 NoAnimReloadDuration=0.2、ReloadDurationPerAmmoCount=0.5，CurrentAmmo 为 37→34。

结论：此场景已确认服务器接受自动换弹，尚未证明服务器零时长换弹或相对原生流程提速。基线没有记录按 R 时刻，不能拿“最后一枪到补满”直接比较换弹耗时。120/2000ms、单机 authority、无弹药、弓、泰克榴弹发射器与卸载恢复仍待验证。
