# 任意人物与坐骑超重移动可行性复核

日期：2026-09-26。目标是普通玩家在任意服务器，使人物或任意坐骑超过各自负重上限后仍可正常行走。按用户补充，本轮不研究“高机动”词条。审查依据为 `开发文档.md` §18 的反射、原生链、双端判据；没有更改游戏进程、测试服、插件或本项目功能代码。

## 版本与证据

- 当前客户端 `ArkAscended.exe` SHA-256：`7A08EF6EA5D2050708D02DC451632AD2A245C7D689A8065B2D90C16443C3CC96`，与开发文档中的 93.37.0 / CL 831297 适配记录一致。
- 独立测试服 `ArkAscendedServer.exe` SHA-256：`a2aee3fd6c233b26cdbd2f640c35c36962dad9acee5ef8bd83dc5df38a1422e7`。反汇编以同 SHA 的 ArkApi 符号缓存定位，来源见 `release/diagnostics/weight-review-20260926/server-native/provenance.json`。
- 本轮分别对客户端 PID 632 和独立测试服 PID 31260 做只读反射快照，位于 `release/diagnostics/weight-review-20260926/client/` 与 `server/`。快照证明所观察实例的类、字段和默认值，不构成超重移动实验。

## 路径审查

| 路径 | 证据 | 结论 |
| --- | --- | --- |
| 本地修改重量、上限或速度 | `UPrimalCharacterStatusComponent.GetMovementSpeedModifier` 的服务端 RVA `0x5123180` 读取服务端当前重量（`0x89c + 0x8cc`）及最大重量（`0xf4`），按重量比和 `WeightSpeedDecreasePower` 计算速度倍率；重量比达到 1 时倍率趋于 0。既有 `服务器移动纠正反汇编-20260925.md` 证明服务器独立模拟并纠正移动。 | 客户端单边修改无法满足“任意服务器持续认可超重位移”。本轮没有投入功能代码实验。 |
| 服务器原生 `InfiniteWeight` | `UShooterCheatManager.InfiniteWeight` 服务端 RVA `0x4d21ae0` 切换状态组件 `0xbdc` 的 `0x80` 位并调用 `UpdateWeightStat`；`UpdateInventoryWeight` 读取此状态或游戏模式 `bForceInfiniteWeight`，设置 `MaxInventoryWeight` 为约 1,000,000。`UpdateWeightStat` 在该状态下将计算重量清零。 | 确实是服务器认可的无限负重机制，但不等于普通客户端可触发。 |
| 把管理员命令当普通 RPC | `AShooterPlayerController.RemoteServerCheat_Implementation` 服务端 RVA `0x4ee2350` 在调用 `ServerCheat` 前检查控制器 `0xab8` 的权限位；`ABasePlayerController.ServerCheat_Implementation` 服务端 RVA `0x4a7a790` 另有管理员 IP/权限检查。 | 已有明确的服务端权限门；不能将 SDK 暴露的函数名视作无权限入口。 |
| 骑乘重量分摊 | `UPrimalCharacterStatusComponent.UpdateWeightStat` 服务端 RVA `0x5130f90` 从坐骑背包取重量，并在有骑手时用骑手状态重量乘 `DinoRiderWeightMultiplier`，还计入乘客/承载系数。当前快照的恐爪龙、穴角兔状态实例 `DinoRiderWeightMultiplier` 均为 1。 | 特定生物或装备减重即便成立，也不能覆盖人物及任意坐骑超出自身上限的目标。 |
| `ShouldEncumberBasedOnDino` | 基类服务端 RVA `0xfeb260` 直接返回 false；恐龙覆盖 `0x53521e0` 只在野生/驯养等条件组合下返回 true。 | 这是特定坐骑关系的额外判定，不是通用的“忽略自身负重”开关。 |

原生证据文件位于 `release/diagnostics/weight-review-20260926/server-native/` 与 `server-admin-impl/`。以上结论是对这套独立测试服二进制和当前已加载实例的审查；没有针对所有官方服务器版本进行动态调用追踪。

## 本轮结论与验收界线

目前找到的**可确认生效**路径需要服务器侧修改状态或配置；没有找到让无管理员权限客户端在任意服务器触发它的原生入口。骑乘重量计算不是一个可推广到人物与任意龙的豁免。故不能把“任意人物/龙，超上限仍行走”标为已实现或可交付。

若后续发现新的普通玩家入口，按 §18 顺序先核实实际类和调用条件，再在隔离服做四组对照：人物、骑手超重、龙自身超重、上下坐骑后的持续状态。每组记录客户端与服务端当前/最大重量、速度、位移与纠正，要求服务端重量仍超过上限且持续认可正常位移；本地动画或短暂位移不计成功。当前没有这类动态验收证据。
