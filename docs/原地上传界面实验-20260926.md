# 原地上传界面实验结果（2026-09-26）

## 目标与实测

目标是在地图任意位置打开截图所示原生贡品/传送界面，并让物资、恐龙、人物跨服操作由服务器接受；目标服务器包含无法安装服务端插件的其他服务器。

首版把人物自身 `MyInventoryComponent` 标为贡品背包，再调用 `AShooterHUD::ShowInventory`。DLL 构建和语言检查通过，但用户实测点击后**只打开人物背包**。该入口已撤回，菜单恢复为明确依赖真实方尖碑的原生终端入口。

## 根因

当前客户端的 `AShooterHUD::ShowInventory` 原生实现会比较传入背包与人物自身背包（`release/diagnostics/upload-core-20260926.txt`，`6a6c966–6a6c987`）。相同或空指针会切到本人物背包分支，并将 `UUI_Inventory::bHasRemoteInventory` 设为 false（`6a6c9d5`）。因此更改背包的 `bIsTributeInventory` 标记不足以显示远端贡品栏。

`AShooterPlayerController::ViewingAnUploadTerminal` 会遍历控制器已登记的远端库存，并检查对象标记、所有者及距离（同一诊断记录 `66f05a0–66f0875`）。仅客户端创建一个假远端背包可能显示贡品布局，但服务器没有对应的已复制对象和访问会话，原生上传 RPC 无法据此获得物资、恐龙、人物传服权限。早期单独创建集群服务器列表也只验证了列表显示，没有上传成功回调或有效传服上下文。

## 当前边界

在不能修改目标服务器的条件下，现有 SDK/原生路径没有可确认的“任意地点真实上传会话”入口。若将来发现可用的客户端原生路径，仍须按开发文档 §18.5 同时验证：服务器是否登记了远端库存、上传 RPC 是否被接受、上传成功回调、重新登录后的物资/恐龙/人物状态，以及真实跨服 travel。仅凭客户端窗口外观不能判定功能完成。
