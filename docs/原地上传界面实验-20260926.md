# 原地上传界面实验（2026-09-26）

## 目标

在地图任意位置打开截图所示的原生贡品/传送库存界面，不查找或借用方尖碑、贡品终端、泰克传送器等建筑。

## 本轮实现

- 菜单「工具 → 笔记与上传」中的按钮改为「实验：原地打开上传面板」。点击后在游戏线程调用 `AShooterHUD::ShowInventory`，关联人物自身的真实背包组件。
- 仅在界面打开期间将人物背包的 `bIsTributeInventory` 与 `bAllowAddingToArkTribute` 置位；关闭、死亡、换图、人物/背包变化、卸载时恢复原值。不会创建建筑，也不会发送建筑远程背包打开/关闭 RPC。
- 面板期间暂停其它自动容器会话。物资、恐龙、人物上传仍使用游戏原生交互及服务器判定，不由客户端伪造成功反馈。

## 尚未验证

本轮没有运行中的 `ArkAscended.exe` 或测试服务器，因此尚不能确认 `ShowInventory(人物背包)` 是否完整生成截图中的右侧贡品页，也不能确认服务器是否接受从此界面触发的物资、恐龙、人物上传或跨服操作。即使 UI 显示成功，服务器也可能因为缺少真实终端会话或距离条件而拒绝。按钮和状态文本明确标为实验。

实机验证应先使用独立测试存档与无价值测试物品，依次核对：界面三栏与贡品分页、物品上传后的服务器库存与重新登录结果、驯龙上传后的服务器生物状态、最后才测试人物传服及跨服列表。人物传服可能改变当前角色与连接状态，应保存测试存档。按开发文档 §18.5 同时采集客户端与服务器状态，失败时再定位 `ViewingAnUploadTerminal`、`ServerAddItemToArkInventory`、`ServerUploadDino`、`ServerUploadCurrentCharacterAndItems` 的前置条件。
