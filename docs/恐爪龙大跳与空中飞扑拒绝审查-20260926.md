# 大跳与空中飞扑拒绝原因审查（2026-09-26）

结论：目前至少存在两层不同问题。大跳与点扑跃的同时开启被本项目的实验隔离逻辑直接禁止；历史记录中另有一次已发出的请求被服务器结束，附近采样显示起点偏差超限。不能把两者都称为服务器不允许“大跳后飞扑”。本次审查未修改运行功能或服务器逻辑。

## 已确认：客户端开关互斥

`DeinoGlideProbe.inl::DeinoProbeMode` 将 `bDeinonychusBigJump` 并入 Other，`DeinoActionRules.h::Mode` 在 Other 为真时返回 0。点扑跃又要求记录模式为 4 且 `DeinoProbeMode()==4`，否则直接返回。

因此当前版本只要大跳和点扑跃两项真正同时为开，点扑跃就不会提交。这里没有“大跳倍率太高才拒绝”的门槛，也不是服务器拒绝。

如果在已经开始的记录中途打开大跳，会以 `conflicting_movement_feature` 结束记录并置 Done。随后只关闭大跳还不够，需要关闭再开启实验来重新开始记录。若尚未开始记录则没有这个 Done 锁存。旧点扑跃状态文字可能保留“已提交”，不能据此认定刚才那次 F6 已发送。

大跳实际只调 `UberpounceJumpSpeed`，由原生 `ComputeJumpVector → ServerRequestJump` 使用；没有发现该字段本身是 `ServerRequestUberpounce` 的拒绝参数。移除实验互斥和证明组合稳定有效是两个不同工作。

## 强证据：已提交请求的起点不同步

记录：`deino-glide-20260926-154239-632-19906781.csv`，8312 ms 请求。

- 8312 ms 有 `own_point_pounce_request`、`ClientStartUberpounce` 调用/返回标记，说明通过了客户端门槛。
- 8359 ms 收到 `MultiEndUberpounce`，距请求约 47 ms。
- 服务器 `UberpounceStartLocation` 更新为这次上报起点，但目标队列仍保留上次目标，没有进入本次准备/扑跃状态。
- 请求后约 43 ms 的只读采样中，上报起点与服务器位置相距 **415.04 cm**。
- 已解析服务器入口在 `0x140a–0x1500` 检查当前位置与上报起点，要求距离严格小于 `UberpounceHackDistCheck`；采集值为 **120 cm**。检查失败进入 `0x70a → MultiEndUberpounce`。

这条证据链支持“起点不同步超限”是该次拒绝的主要候选。服务器约 50 ms 采样、两端时钟映射有约 16 ms 波动，没有在判断语句执行瞬间抓取数据，因此不能把近邻采样当成精确分支命中证明。

该次请求实际通过了本版的“大跳互斥”门槛，因此不能据此声称这是大跳和点扑跃同时开启时的失败样本。大跳更高速度可能放大移动同步误差，但需要允许组合后的新记录验证。

## 其他已核对门槛

| 层次 | 条件 | 当前证据 |
| --- | --- | --- |
| 客户端 | F6 必须先松开再按；冷却 3 秒，冷却内按下不排队 | 可造成按了没反应；旧状态文字不会自动清空 |
| 客户端 | 记录必须正在进行；菜单、失焦、下骑或记录超时结束后需重新开关 | 属于尚未提交 |
| 客户端 | Falling 且抓附状态 0，或允许的抓附状态 2；上一跳跃请求与速度缓存必须空闲 | 空中上升和下降均可属于 Falling，不是必须到最高点才能调用 |
| 服务器 | 被携带/乘客状态、最近被携带时间 | 失败进入结束链；本次历史采样未覆盖全部值 |
| 服务器 | 起点距离检查 | 上述失败样本有超限强证据 |
| 服务器 | 解析目标距离小于最大范围乘约 1.1 | 当前最大范围 3500 cm，对应约 3850 cm；本轮目标 3000 cm |
| 服务器 | 当前到目标的通道 15 路径检测 | 命中障碍会拒绝，不能仅凭准星无目标判定路线无阻挡 |
| 服务器 | 更新目标队列后扣耐力 | 失败样本队列未换成新目标，不支持把“扣耐力失败”当作首要解释 |
| 服务器 | 目标类型/扑跃状态分派 | 已解析入口没有要求必须 Walking；此前三次从空中状态 0 成功已作动态对照 |

## 修正与验证顺序

1. 只对点扑跃模式允许搭配恐爪龙大跳，保留其他运动实验互斥；记录实际开关、倍率、请求速度和每次本地阻止原因。其他诊断模式继续保持基线隔离。
2. 分别测试普通跳跃/大跳中单次 F6，区分客户端未提交、服务器结束和成功进入扑跃。
3. 对已提交但结束的请求，核对服务器上报起点、实时位置、目标距离和路径；在具备证据后处理请求时序与同步问题，不先扩大目标距离或假定速度不足。

本轮没有更改服务器判定，没有把起点清零或伪造起点来绕过检查。

## 后续修复

按用户要求，已修改模式规则：大跳只允许与点扑跃模式 4 组合，不会放开其他诊断模式或其他运动功能。点扑跃重新开启时重置旧状态文字；F6 单次按下现在区分模式冲突、记录未就绪/结束、冷却、状态/缓存不符，并记录大跳倍率、当前速度与动作状态。无效按下不排队，按住不会在冷却结束后突然发送。

离线规则覆盖扩展为 128 种开关组合，新增输入阻止/冷却/松键语义回归。服务器只读采样增加起点容差、范围、携带状态及跳跃参数；服务器判断逻辑未修改。该修复解决已确认的客户端互斥和提示问题，起点不同步造成的服务器拒绝仍需大跳组合实测定位。重测见 [实验步骤末节](恐爪龙空中点扑跃实验-20260926.md)。
