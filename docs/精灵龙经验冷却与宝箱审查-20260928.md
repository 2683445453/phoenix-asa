# 精灵龙经验冷却与宝箱审查（2026-09-28）

审查对象为 ARK: Survival Ascended 的精灵龙（Drakeling，原生资源名称 `ShoulderDragon`）。本次只读检索项目、客户端反射和公开一手资料，没有修改游戏内存、发送游戏 RPC、发放经验或生成宝箱，也没有改动 phoenix 功能。

## 结论与证据等级

**赋予 CD、储存经验倍率／上限、钥匙门槛及宝箱品质／数量都有明确的服务器侧修改点。原生链会在服务器重新检查冷却，并在服务器增减经验、发钥匙；仅修改 phoenix 客户端字段不能改变这些权威结果。** 本次已读取当前本体和武器蓝图，以下区分已读到的逻辑与仍未加载的经验监听 Buff、宝箱具体类。没有进行修改效果实测。

| 审查项 | 当前结论 | 证据边界 |
| --- | --- | --- |
| 赋予经验冷却 | `ConsumeStoredXPInterval=300` 秒，服务器按网络时间重新检查 | 本地请求限频另为 0.25 秒；改它不能去掉技能 CD |
| 精灵龙储存经验 | `MaxStoredXP=30000`，当前等级 1～400 映射 0.25～2 倍，入库后夹取上限 | 入库公式已读；上游哪些 XP 事件及 Actual／Expected 取值仍需 XP 检测 Buff |
| 发放钥匙 | 至少 5000 储存经验；品质由 5000～30000 映射至约 0～10 | 服务器在清空储存经验之前生成 |
| 宝箱品质、数量 | 本体明确设置 SupplyCrate 品质和 `ItemSets`，且有独立倍率、等级档位 | 宝箱具体类的接口实现及 ini 覆盖生效时序仍未核完 |
| 环境 Buff 经验与掉落品质 | 当前客户端实际读到经验倍率约 1.1、宝箱品质倍率 1.1，持续时间字段 10800 秒 | 这是 `Buff_ShoulderDragonBiome_C`，不能冒充储存经验或赋予技能冷却 |

## 赋予经验 CD：服务器检查的是 300 秒

本体默认值、秋季子类默认值和当前实例的关键设置一致：

| 本体字段 | 当前偏移 | 值／用途 |
| --- | --- | --- |
| `LastConsumeStoredXPTime` | `0x2D28` | 上次成功转赠的网络时间，网络复制 |
| `StoredXP` | `0x2D30` | 储存经验，网络复制／保存 |
| `SavedLastConsumeStoredXPCooldown` | `0x2DD0` | 保存的剩余冷却 |
| `MaxStoredXP` | `0x2DE8` | 30000 |
| `MinStoredXPForTreasure` | `0x2DF0` | 5000 |
| `ConsumeStoredXPInterval` | `0x2E18` | 300 秒 |

调用链为：`StartSecondaryActionEvent → Server_RequestShoulderDragonAttack → AttemptShoulderDragonAttack → 本体 GetDragonWeaponState`。

- 武器 `Server_RequestShoulderDragonAttack` 确有 Net／NetReliable／NetServer 标志，只接收 `IsBite, Loc, Dir`，不接收客户端指定的经验值或冷却结果。
- 武器 `AttemptShoulderDragonAttack @0xBC–0x157` 区分网络模式，只有单机、专服、本地主机进入实际分支，Client 分支退出；专服另检查攻击动画。
- `AttemptShoulderDragonAttack @0x57F–0x638` 在执行端调用本体 `GetDragonWeaponState`，要求返回进度至少 1。
- 本体 `BPGetCustomBlueprintData @0x270–0x4AC` 在模式 2 选择 `LastConsumeStoredXPTime` 与 `ConsumeStoredXPInterval`，将网络经过时间映射为 0～1 的冷却进度。
- `BPLocalExecCommand @0xA–0x57` 再次要求服务器；成功转赠后 `@0x399–0x3EE` 写入新的网络时间并同步。

所以改客户端 `ConsumeStoredXPInterval`、`LastConsumeStoredXPTime` 或 HUD 进度，最多改变本地表现；发送请求后服务器仍使用自己的字段。`LastLocalRequestAttackTime` 的 0.25 秒只是客户端防止连续请求的间隔，与上述技能 CD 独立。

原版还有创造模式分支：`UseWeaponAbilityCheatInterval` 检查背龙玩家是否具有控制器指定的 `CreativeModeBuff`；模式 2 使用 **1.5 秒**间隔。它仍在服务器侧判定，不能把本地伪造创造状态解释为可跳过服务器冷却。

`BP_OnCryo`、`BPPreServerUploadDino` 调用 `UpdateSavedStoredXPCooldown(false)` 保存剩余 CD；`BPDinoARKDownloadedBegin` 调用 true 分支重建上次时间。已看到原生保留冷却的逻辑，不能假设冷冻／上传必然洗掉 CD。

## 经验获取和转赠：两段不同的计算

本体 `BPLocalExecCommand(AddStoredXP)` 已完整读到，先要求服务器及有效背龙玩家，然后执行：

```text
等级倍率 M = MapRangeClamped(当前等级, 1, 400, 0.25, 2)
StoredXP = clamp(旧 StoredXP + 输入经验 X × M, 0, MaxStoredXP)
```

具体证据：`BPLocalExecCommand @0x773` 读取 `GetCharacterLevel()`，`@0x7EF` 夹取线性映射，`@0x838–0x911` 乘以 `ExecParams.FloatParam1`、相加并夹取到 0～30000，最后更新并复制 `StoredXP`。1 级 0.25 倍、400 级及以上 2 倍；150 级约 0.9035 倍，300 级约 1.5614 倍。

**X 的上游来源仍有边界：** `BPOnSetMountedDino` 的服务器分支给精灵龙挂载 `Buff_ShoulderDragonCheckXP`，当前客户端没有加载该 Buff 的具体蓝图，尚不能独立核实其完整 XP 类别筛选及 Actual／Expected 经验选择。不得把上述 X 直接等同玩家面板增长的经验。肩载 Buff 的 `BPPassHarvestExperienceToActor` 只允许目标为该玩家的 `MountedDino`，不是储存经验计算器。

转赠由武器执行，模式 2 下：

```text
实际给目标的经验 = min(目标最大经验 − 目标当前经验, 精灵龙 StoredXP)
若实际给出的经验 > 0：写入 CD → 按原 StoredXP 尝试发钥匙 → StoredXP 清零
```

武器 `AttemptShoulderDragonAttack @0x1674–0x190D` 直接更新目标 `ExperiencePoints` 与复制字段，未经过普通 `AddExperience` 倍率链；`@0x7E1–0x9B0` 用实际转赠量通知本体。本体 `BPLocalExecCommand @0x339–0x4DD` 要求量大于 0，先尝试生成钥匙再将储存经验全部清零。因此目标尚能接收正数经验、但剩余额度不足时，不会保留未能接收的储存经验；钥匙依据的仍是清空前的原存量。已满经验目标会被拒绝；实际转赠量为零不会触发这段 CD／清零。钥匙生成另有门槛与资源检查，即使尝试失败，后续仍执行储存清零。

目标限制也已确认：同队、存活恐龙、非幼体、`bIsMounted=false`、允许获取经验且未达经验上限；禁止精灵龙本类及子类。武器默认 `XPTraceDistance=2000`（UE 单位，约 20 米），执行球形射线命中检查。不能向任意角色或任意距离直接转赠。

## 钥匙和宝箱：品质、数量分开控制

`AttemptSpawnTreasureMap` 要求有效玩家控制器、人物、背包、钥匙资源，以及 `StoredXP>=5000`。当前实际输出范围是 `[0.000001, 10.000001]`，不是精确的 `[0,10]`：

```text
钥匙生成品质 Q = 0.000001 + 10 × clamp((StoredXP − 5000) / 25000, 0, 1)
```

`@0x1BF` 进行映射，`@0x242` 将 Q 作为 `AddNewItem` 的 `ItemQuality` 和 `MinRandomQuality`。20000 储存经验对应约 6，30000 对应约 10。另一个 `GetTreasureItemQuality` 辅助函数存在难度相关输出，但实际发钥匙函数没有调用它，不能将其难度公式混入这里。

精灵龙的 `BPTimerServer @0x1C` 调用 `TreasureTick`。该函数要求已驯服、肩载人物有效、挖宝库返回 CanDig、钥匙及宝箱资源有效，然后延迟生成 SupplyCrate，修改品质与奖励数组，再完成生成并消耗钥匙。

| 本体控制字段 | 当前值 | 已读到的用途 |
| --- | --- | --- |
| `MapToTreasureQualityMultiplier` | 1 | 宝箱 Min／MaxQualityMultiplier = 钥匙 `ItemRating` × 此值 |
| `MapToTreasureQuantityMultiplier` | 1 | 参与次级奖励条目的 Min／MaxQuantity 缩放 |
| `ExTreasureItemEveryNumLevels` | 75 | 当前等级每 75 级增加一档 |
| `AbsMaxExTreasureIncrements` | 8 | 档位上限 |
| `ExSecondaryItemsMultiplierPerLevelRange` | 0.1875 | 次级奖励数量每档增量 |

```text
N = min(1 + floor(当前精灵龙等级 / 75), 8)
第一套奖励 ItemSets[0]：MinNumItems = MaxNumItems = N
其他套内条目：
  新 Min/MaxQuantity = max(原数量 × 钥匙 ItemRating × 数量倍率 × (1 + N × 0.1875), 1)
```

这里的 N 是奖励套的抽取条目数及传给宝箱接口的档位，不应说成必定获得 N 个独立物品。`TreasureTick` 还调用宝箱接口 `Set Treasure Quality Level(N)`；当前没有加载 `SupplyCrate_BuriedTreasure_ShoulderDragon_C` 的具体实现，不能给出完整物品池、各奖励概率或最终四舍五入规则。

实际资源软引用已确认：

- 钥匙：`/Game/ASA/Dinos/ShoulderDragon/Chest/PrimalItem_TreasureMap_ShoulderDragon.PrimalItem_TreasureMap_ShoulderDragon_C`
- 宝箱：`/Game/ASA/Dinos/ShoulderDragon/Chest/SupplyCrate_BuriedTreasure_ShoulderDragon.SupplyCrate_BuriedTreasure_ShoulderDragon_C`

**可修改性判断：** 服务器模组／插件可调上述字段、钥匙门槛、储存上限与等级倍率，并修改生成后的奖励。原版 `ConfigOverrideSupplyCrateItems` 可作为按类覆盖物品池的候选，但本体会改写 ItemSets，宝箱还接收专用接口回调；未核实覆盖时序前，不能保证某条 ini 即可完整覆盖。客户端修改钥匙显示品质或本地箱子数组不能创建服务器认可的奖励。

## 已发布模组提供的可修改证据

[Drakeling Tweaks 作者发布页](https://www.curseforge.com/ark-survival-ascended/mods/drakeling-tweaks)说明，该模组适用于已有及以后生成的精灵龙，无需替换生物类；恢复非野生击杀储存经验，支持三种技能冷却与关闭宝箱奖励。

[作者当前配置文档](https://github.com/maglucen/asa-mods-docs/blob/main/drakeling-tweaks/configuration.md)在 `GameUserSettings.ini` 的 `[DrakelingTweaks]` 节提供：

| 配置项 | 作用 |
| --- | --- |
| `GiftOfFortuneCooldownMultiplierPercent` | 该技能冷却占当前默认值的百分比；100 原值、50 一半、1 百分之一，0 接近无冷却 |
| `NonWildKillXPPercent` | 驯服／未认领击杀的储存经验恢复比例；支持超过 100，0 沿用官方行为 |
| `DisableHoardChests` | True 时转赠储存经验不发放宝箱奖励 |

这些是**该模组读取的自定义键，不是原版通用 ini 设置**。该模组的非野生经验倍率不改变野生击杀经验。

[作者实现记录](https://maglucen.com/devlog/drakelingtamedxpmultiplier-eventdriven-buff-hook/)给出了实际入口：玩家 Buff 监听肩载 Buff 的出现／移除，通过 `Buff_ShoulderDragonMounted.BuffDamageCauser` 找到精灵龙，再在龙身上监听 `BPNotifyExperienceGained`，针对 `XP_TAMEDKILL` 和 `XP_UNCLAIMEDKILL` 使用 `ExpectedExpGain` 计算补入值。这为服务器模组提供了具体实现方向；并非验证过的 phoenix 客户端路径。该文章中的旧 CD 配置名与当前配置文档不同，使用时以当前配置文档为准。

## 版本变化与资料辨别

## SDK 中可确认的边界

当前 SDK 没有精灵龙专用蓝图，只有 `VictoryCore` 的 ShoulderDragon DLC 拥有权检查声明；这些声明没有提供经验／CD 的实际逻辑。本次专用结论来自运行时捕获。

| 证据文件（`src/external/CppSDK/SDK/` 下） | 位置 | 可确认内容 |
| --- | --- | --- |
| `ShooterGame_classes.hpp` | 4829–4830 | `ExperiencePoints` 为持久字段，`ReplicatedExperiencePoints` 为网络复制字段 |
| `ShooterGame_functions.cpp` | 29617 | `AddExperience` 是普通 Native／BlueprintCallable 函数，未标记为 NetServer RPC |
| `ShooterGame_functions.cpp` | 181951 | `ServerMultiUse` 是服务器 RPC，但只传目标和交互索引 |
| `ShooterGame_classes.hpp` | 12720 | 游戏模式有 Config 类型 `ConfigOverrideSupplyCrateItems` |
| `ShooterGame_structs.hpp` | 2615–2673 | 掉落结构可描述物品、数量、品质、概率、图纸概率、套数及目标宝箱类 |
| `ShooterGame_functions.cpp` | 154410、154448 | `GenerateCrateItems`／`GenerateCustomCrateItems` 没有 NetServer 标记 |

这些 C++ 文件是反射声明和调用包装，不包含精灵龙实际分支。仅在客户端调用 `AddExperience` 或生成奖励函数，不能据此认定远程服务器接受了变更。
