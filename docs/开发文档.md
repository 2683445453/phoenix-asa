# phoenix 开发文档 — 项目架构与开发指南

> 本文档面向开发者，说明 phoenix（Begeerte-ASA-main）的项目架构、构建方式、核心子系统与扩展方法。
> 面向使用者的说明见 [`phoenix-使用说明.md`](phoenix-使用说明.md)；功能的「代码位置速查」见 [`开发文档-功能索引.md`](开发文档-功能索引.md)；历次版本的功能范围与验证记录见 `docs/phoenix-*.md` 系列与仓库根目录 `README.md`（含 Lua API 参考与游戏更新适配记录）。

---

## 1. 项目概览

phoenix 是一个注入到 **ARK: Survival Ascended（ASA）** 客户端进程（`ArkAscended.exe`）的 DLL，附带一个独立的注入器（loader，输出名 `phoenix.exe`）。它通过 D3D12 钩子呈现 ImGui 菜单，通过游戏虚表（VMT）钩子与 MinHook 内联钩子接入游戏循环，读取由 Dumper-7 生成的 UE5 SDK 来访问游戏对象，并只调用游戏原生 RPC 与输入入口与服务器交互。

| 项 | 说明 |
| --- | --- |
| 语言/标准 | C++20，MSVC（Visual Studio 2022+ Build Tools） |
| SDK | `src/external/CppSDK`，Dumper-7 生成；偏移断言在 `Assertions.inl` |
| 图形与菜单 | 自研 D3D12 Hook（`external/Minimal-D3D12-Hook-ImGui`）+ ImGui |
| 绘制后端 | Shadow-Gui（`external/Shadow-Gui`，后台 DrawList） |
| 游戏钩子 | ezVMT（虚表）、MinHook（内联 detour）、AOBScan（特征码） |
| 脚本扩展 | LuaJIT 2.1 + sol2，Lua 5.1 |
| 授权 | `licensing/`，`PHOENIX_LICENSE_ENABLED` 编译开关；开发版默认关闭 |
| 产物 | `phoenix.dll`（注入模块）+ `phoenix.exe`（注入器） |

核心设计原则：

1. **只读 + 原生交互**：尽量读取游戏状态、调用原生函数/RPC；服务器校验（距离、权限、冷却、伤害）一律保留。
2. **修改必须可恢复**：对字段/标志的修改记录原值，关闭功能、换武器、切图、卸载时恢复（见 `FloatTuning`、`ExtensionObject`、`PrepareRuntimeForUnload`）。
3. **对象生命周期防御**：UE 对象一律用「指针 + 索引 + 序列号」三重校验（见 §13）。
4. **新功能默认关闭**，配置持久化，纳入「停止自动化」清单。

### `src/internal` 中的「域级模块」

`Hack/` 目录把一个巨型实现拆成「主文件 + 域级扩展」：

- `Hack.cpp`（约 7700 行）：通用工具、状态函数、以及大多数直接写在主文件里的功能（自动喂食、吃喝、修理、钓鱼、自动制作、换甲、飞行龙等）。
- `*.inl`：以 `#include` 方式并入 `Hack.cpp` 末尾的域模块（详见 §11）。
- `*Rules.h`：纯逻辑头文件（筛选、分类、调度规则），便于离线单测。

## 3. 构建与发布

### 3.1 前置条件

- Visual Studio 2022（Build Tools 亦可），需要 MSBuild 与 C++ 桌面开发组件；脚本用 `vswhere.exe` 定位 MSBuild。
- 全部第三方依赖已随仓库提供（CppSDK、MinHook、ImGui、LuaJIT、sol2、Shadow-Gui、ezVMT、AOBScan），无需另行拉取。

### 3.2 构建命令

```powershell
# 开发版（不启用授权/保护壳）→ dist/phoenix + dist/phoenix.zip
./build-release.ps1
# 本地授权验证版 → dist/phoenix-local-license + 同名 ZIP
./build-local-license.ps1 -LicensePort 17891
```

脚本流程：MSBuild 编译 `src\...sln`（Release/x64，`/m:2`）→ 编译 `ASA_Loader\ASA_Loader.sln` → 拷贝 DLL/语言/Lua/文档 → `phoenix.exe --check` 自检 → SHA256 → 打包 ZIP。

只编译 DLL 验证改动（开发常用）：

```powershell
& "$env:ProgramFiles(x86)\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * -requires Microsoft.Component.MSBuild -find 'MSBuild\**\Bin\MSBuild.exe' |
  % { & $_ src\begeerte_ark_survival_ascended.sln /t:Build /p:Configuration=Release /p:Platform=x64 /m:2 /nologo /v:minimal }
```

输出 DLL 位于 `release/phoenix.dll`（开发版）。

### 3.3 授权编译开关

- `licensing/LicenseBuild.props` 提供 `PhoenixLicenseMode`（Development / Local）与 `PHOENIX_LICENSE_ENABLED`。
- `dllmain.cpp` 中 `#if PHOENIX_LICENSE_ENABLED` 决定是否启动 `phoenix::license::Start(...)`；`hooks.cpp` 的 `ShouldBypassFeatures()` 会持续检查 `phoenix::license::IsAuthorized()`，未授权时所有功能回调旁路。

### 3.4 离线回归测试

`tests/` 下每个 `run-*.ps1` 用 `cl.exe` 编译对应独立 `.cpp`（不注入游戏）并断言输出。覆盖：瞄准选取、泰克长矛、自动制作调度、采集寻路、水下武器、背包工具、接口渲染（`PHOENIX_UI_TEST` 离屏 ImGui）、D3D12 后端生命周期、VMT 重注入、语言包完整性（`language_package_integrity.py`）、授权流程（`test_licensing.py`）等。新增逻辑尽量配一个可离线验证的单测。

## 4. 启动与初始化时序

`src/dllmain.cpp`：

```
DLL_PROCESS_ATTACH
  └─ CreateThread(MainThread)
       ├─ InitializeStartupLog()          → logs/phoenix_dll_<时间>_PID<n>.log
       ├─ [授权版] phoenix::license::Start()；未授权 → RequestUnload() → 退出码 6
       ├─ init(lpParam)
       │    ├─ 等待 SDK::UWorld::GetWorld() 与 UEngine::GetEngine() 就绪（100ms 轮询）
       │    ├─ -lowspec 参数 → bPotatoGraphics
       │    ├─ ConfigManager::Initialize("<模块目录>/cfg") + LoadConfig("phoenix_autosave.ini")
       │    │    └─ 缺失时从旧版 38s_autosave.ini 一次性迁移
       │    ├─ g_MDX12::Initialize()       → 安装 D3D12 钩子（Present/ResizeBuffers/ExecuteCommandLists）
       │    ├─ 注册 7 个游戏回调：
       │    │    SetSetupImGuiDrawCallback(MyImGuiDraw)                 // 菜单帧
       │    │    SetSetupActorTickCallback(g_AActor::Tick)              // 世界帧
       │    │    SetSetupHandleDisconnectCallback(...)                  // 断线
       │    │    SetSetupOutputTextLineCallback(...)                    // 控制台
       │    │    SetSetupPostRenderCallback(...)                        // 渲染
       │    │    SetSetupPhysicsRotationCallback(...)                   // 移动组件旋转
       │    │    SetSetupTakeDamageCallback(...)                        // 伤害
       │    ├─ LanguageManager::Initialize("<模块目录>/language") + FetchWorkshopScripts()
       │    └─ LuaManager::Initialize("<模块目录>/lua") + FetchWorkshopScripts()
       └─ g_Hook::SetRuntimeReady(true)   → 此后功能回调才真正执行（ShouldBypassFeatures 放行）
```

关键点：

- 注入后**必须完整退出游戏再替换 DLL**；已注入进程不会自动热更新磁盘上的 DLL。
- 卸载协议：菜单「卸载」→ `g_Hook::RequestUnload()` → `UnloadWorker`（`hooks.cpp`）等待初始化线程结束 → 等下一个 UpdateCamera/PostRender 游戏线程回调执行 `PrepareRuntimeForUnload()`（关闭功能开关并调用各 Reset/恢复函数）→ `StopAllHooks()`（MinHook 禁用 + ezVMT 移除 + 输入钩子移除）→ `FreeLibraryAndExitThread`。卸载期间 `ShouldBypassFeatures()` 使所有功能旁路。

## 6. 钩子层详解（external/Minimal-D3D12-Hook-ImGui/Main）

### 6.1 钩子清单

| 钩子目标 | 方式 | 定位来源 | OK 标志（hooks.h） | 功能去向 |
| --- | --- | --- | --- | --- |
| IDXGISwapChain3::Present / ResizeBuffers / ExecuteCommandLists | D3D12 VMT（`CheatData::VTable::D3D12`：8/13/10） | 固定槽位 | —（DX12 层） | ImGui 帧、Shadow 后台绘制、覆盖层资源/重置、交换链队列跟踪 |
| AActor::Tick | ezVMT 槽 470 | `CheatData` | `ActorTickOK` | `g_AActor::Tick`（世界帧调度，见 §10） |
| AShooterPlayerCameraManager::UpdateCamera | ezVMT 槽 472 | `CheatData` | `UpdateCameraOK` | 自由相机、`g_Aimbot::Tick()`、卸载时的渲染状态恢复 |
| UMovementComponent::PhysicsRotation | ezVMT 槽 318 | `CheatData` | `PhysicsRotationOK` | `g_Hack::ForceTurn`（秒转头） |
| UGameViewportClient::PostRender | ezVMT 槽 122 | `CheatData` | `PostRenderOK` | ESP/资源/指示器绘制、`g_Aimbot::Tick()` |
| UConsole::OutputTextLine | ezVMT 槽 99 | `CheatData` | `OutputTextLineOK` | 控制台输出 → Lua `OnConsoleMessage`、日志 |
| UNetConnection::HandleDisconnect | AOB | `CheatData::Signature::UNetConnection` | `HandleDisconnectOK` | 断线时清理瞄准/自动化状态 |
| AShooterWeapon::GetAdjustedAim ×4 | MinHook detour | 运行时按 UFunction 解析（`hkAdjustedAim<0..3>`） | `WeaponAimOK` | 魔术子弹方向修正（`g_Aimbot::OverrideWeaponAim`） |
| GetProjectileSpeedModifier / GetProjectileGravityModifier | MinHook detour | 运行时解析 | `ProjectileModifiersOK` | 投射物速度/重力倍率 |
| 霰弹枪散布计算 | MinHook detour | 运行时解析 | `ShotgunSpreadOK` | 弹丸集中 |
| ShooterWeapon.StartFire UFUNCTION 包装 | MinHook detour | `FindUFunction` + 前缀校验 | `InstantThrowOK` | 投掷物瞬间扔出（拦截手雷开火，跳过蓄力直接投出并吞掉原生开火） |
| 泰克弓即时命中 BP（WeapTekBow_C） | 脚本局部变量修正（ViewArguments 校验） | 运行时校验 | `TekBowInstantAimOK` | 泰克弓即时模式方向修正 |
| ShooterWeapon_Projectile 开火事件（Server/ClientsFireProjectile×2） | ProcessEvent 链（`IsProjectileShotEvent`） | 运行时解析 | `ProjectileShotEventsOK` | 投射物预判发射、事件统计 |
| ClientNotifyReconnected / ClientNotifyRespawned / ClientChatMessage / ClientAddFloatingDamageText | AOB 或 `FindUFunction`+MinHook（部分入口当前已停用，见 `init*` 注释） | `CheatData`（部分 OUTDATED） | 对应 OK | 跳过进服/重生动画、聊天屏蔽、伤害浮字 |

> `CheatData.hpp` 中标注 `"OUTDATED"` 的特征码表示当前客户端已不再使用该入口（保留说明），需要时按 §15 流程重新定位。

### 6.2 hooks.cpp 的职责

- `hkActorTick / hkUpdateCamera / hkPhysicsRotation / hkPostRender / hkOutputTextLine` 等各钩子入口统一执行：`CallbackScope`（计数活跃回调）→ `ShouldBypassFeatures()` 判断（运行时未就绪 / 卸载中 / 未授权 → 直接走原函数）→ 调用对应 internal 回调。
- `hkProcessEvent` 链：插入 TekHeat 抑制、放置参数实验、投射物开火事件修正（`g_Aimbot::OverrideProjectileEvent`）。
- `StartAllHooks()`：在 UWorld 稳定后调用各 `init*()`（顺序见 §4 初始化部分）。
- `SupportsWeaponAim(Weapon)`：判定当前武器是否具备可用瞄准接口。
- 卸载屏障：`UnloadBarrier.h`、`g_ActiveHookCalls`、`g_GameRuntimeMutex`，保证卸载时没有正在执行的钩子回调。

### 6.3 手工布局修补（游戏更新后）

SDK 反射拿不到的两处手工布局见根目录 `README.md`「如果游戏更新」：

- `UNetConnection`：`RemoteIPList` / `RemotePort`（当前 `0x1EC8 (0x1F18 - 0x0050)`）；
- `UGameViewportClient`：`EngineShowFlags[0x20]` 位段区（用于关闭后处理实现战斗画质）。

## 7. 配置系统（internal/Config）

### 7.1 声明

- `Configs.h`：`namespace g_Config { inline bool bXXX = false; ... }` 内联变量按功能区注释分组。上限常量统一放 `InterfaceRules.h`（`PhoenixInterface`），菜单滑条与运行时共用（如 `MaxAimDistance`、`MaxCameraSpeed`、`MaxSpearTapSeconds`）。
- `FeatureExpansion.inc`：用宏批量声明扩展功能配置：
  ```cpp
  PHX_BOOL(bFastAim, false)
  PHX_FLOAT(DinoMoveSpeedMultiplier, 2.0f, 0.25f, 5.0f)
  PHX_COLOR(ArmorQualityColor, 0.8f, 0.65f, 1.0f, 1.0f)
  ```
  `Configs.h` 顶部 `#define PHX_* → inline ...` 后 `#include` 该文件完成声明；`ConfigManager.cpp` 用同样的宏在保存与加载两处再次 `#include`，实现「一份清单，声明+存取」。

### 7.2 存取

- `ConfigManager.cpp` 按段（`[Misc]`、`[Aimbot]`、`[Triggerbot]`…）写 `phoenix_autosave.ini`。宏：`CONFIG_BOOL/FLOAT/INT/COLOR/STRING`（保存）、`LOAD_*`（加载，键存在才覆盖，缺键保留默认值）。
- 保存时机：菜单关闭时、每 10 秒定时、卸载前；「配置管理」页可命名另存/读取。
- 旧版迁移：`phoenix_autosave.ini` 不存在时读 `38s_autosave.ini` 并另存为新名；个别功能做了旧字段迁移（如旧「独立自动换盾」并入换甲部位开关，见 `ConfigManager.cpp` 中 `bAutoSwapShield` 迁移块）。
- 加载后对数值做 `PhoenixInterface::FiniteClamp` 钳制，防止手工改坏 ini。

### 7.3 新增配置项的标准步骤

1. `Configs.h`（或 `FeatureExpansion.inc`）加变量，**默认关闭/默认安全值**；
2. `ConfigManager.cpp` 保存段与加载段各加一行宏；
3. 需要迁移旧值时在加载段写迁移块；
4. 需要进入「停止自动化」的开关加进 `Menu/FeatureShortcuts.h::StopAll()`（见 §9.4）；
5. 卸载恢复：会改动游戏状态的开关要在 `hooks.cpp::PrepareRuntimeForUnload()` 中关闭并调用恢复函数。

## 8. 语言系统（internal/Language）

- `LanguageManager`：单例。`RegisterDefaults()` 用 `InterfaceText.inc` 的 `PHOENIX_TEXT("...")` 宏注册全部界面文本键；`LoadLanguage()` 解析 ini 后 `ApplyToStaticMembers()` 更新静态成员，并把 `Text.` 前缀键装入翻译表。
- 键算法：`TextKey(Source)` = **FNV-1a 64 位**（offset `14695981039346656037`，prime `1099511628211`，对 UTF-8 字节），格式化 `Text.%016llx`。ini 的 `[Text]` 段里写**裸 16 位小写 hex 键**，加载时自动补 `Text.` 前缀。
- 菜单里一律写 `Tr(U8("中文源文本"))`（`ConfigImGui.h`），缺失翻译回退中文源文本。
- 游戏线程状态字符串用 `LanguageManager::Get().TranslateCopy(...)`（持锁返回副本），渲染线程用 `Translate(...)`。
- 新增文本步骤：
  1. `InterfaceText.inc` 加 `PHOENIX_TEXT("...")`；
  2. 计算 FNV-1a（可用 `tests/language_package_integrity.py` 校验）并追加到 `language/CN.ini`（中文自映射）与 `language/EN.ini`（英文翻译）的 `[Text]` 段；
  3. `language_package_integrity.py` 会检查 ini 与注册文本的一致性。
- `[Language] Locale=en` 与文件名 `EN.ini` 决定 `IsEnglish()`；`FetchWorkshopScripts()` 支持工坊语言包（`Language_Menu.cpp`）。

## 10. 世界帧调度（internal/AActor/Tick.cpp）

`g_AActor::Tick` 是自动化功能的**串行调度中心**（每个 UWorld 帧执行一次，带诊断计数）：

```cpp
g_Hack::AutoFishingQTE(world);
g_Hack::AutoEatDrink(world);
g_Hack::AutoUseBrews(world);
g_Hack::AutoBuffSoup(world);          // 汤类增益到期自动续
g_Hack::AutoFireExtinguish(world);    // 着火自动投掷灭火手雷
g_Hack::AutoPickupDroppedItems(world);
g_Hack::AutoRepairItems(world);
g_Hack::MaintainFishingRod(world);
g_Hack::PumpShotgunNoReload(world);
g_Hack::SuperFlyer(world);
if (g_Config::bAutomatic) g_Hack::AutoSwapBrokenEquipment();   // 自动换甲（含盾）
g_Util::DropOrUseItem();
LuaManager::Get().Lua_OnWorldTick();
```

秒换弹与弓秒蓄力不在这里调度：它们随 `GameplayExtensionsTick`（`GameplayExtensions.inl` 末尾调用 `InstantReloadTick` / `InstantChargeTick`）在串行本地相机回调中执行，同样在开关关闭时也被调用以恢复上一次遗留的字段补丁。

另外 `GameplayExtensionsTick`、`FeatureExpansionTick`、`TekEquipmentTick` 等域级 tick 在 `UpdateCamera/PostRender` 的串行回调中执行（见 `GameplayExtensions.inl` 注释与 `g_UGameViewportClient::PostRender.cpp`）。

**约定**：这些 handler 即使开关关闭也会被调用，以便恢复状态、重置冷却、更新菜单状态字符串。

### 11.2 通用模式

- **原生 RPC 交互**：自动化的「动作」全部走游戏原生入口，例如 `PC->ServerEquipPawnItem(ItemID)`（换甲/换鱼竿）、`PC->ServerTransferAllFromRemoteInventory(...)`（吸包）、`PC->ProcessEvent(SimulateInputKey)`（长矛招架短按右键）、`ServerRequestInventoryUseItem`（吃喝）。**不要**伪造伤害/命中/权限。
- **字段补丁与恢复**：`FloatTuning`（改值+记录原值+按需恢复）、`ExtensionObject`（弱引用包装）、`FeatureExpansionPatch.inl`（对目标对象字段做一次性 patch，换装备/切图恢复）。禁用/卸载/切图必须恢复。
- **反射读取**：`FindReflectedProperty/GetReflectedNestedFloatAddress/ReadReflectedInt32Value` 等，按名字在类链上找字段，布局变化时代码不用改偏移。
- **状态机 + 冷却**：多数 handler 为「检查就绪（存活、前台、菜单/背包未开）→ 冷却判断 → 每帧至多一次动作」结构；状态写入 `GetXxxStatus()`。
- **每帧只发一个 RPC**：多个待处理动作排队（换甲、取物、修理均如此），避免挤占服务器背包同步。

### 12.1 目标选取流程

1. `Tick()`（由 UpdateCamera/PostRender 每帧调用）确认：人物存活、游戏前台、菜单/背包未开、武器有效。
2. `GetBestTarget()` 遍历 `World->PersistentLevel` + 全部流送 Level 的 Actors：
   - `TargetEnabled()`：按配置筛选类型（玩家 / 野生龙 / 驯养龙 / Boss）；
   - 友方排除：非野生单位经 `g_ESP::GetRelation()`（同部落 / 结盟部落 / 部落名回退，见 `ESP/ESP.cpp`）为 `Team` 则跳过；
   - 网格边界粗筛（`MayOverlapCircle`）→ 刷新目标碰撞（`RefreshAimCollision`，用 `ForceUpdateAimedCharacters_Single`）→ 取头/身点 → 投影到屏幕 → 圆内最近者胜出（`AimScreenRanking`）。
3. 开火时 `RefreshShotPoint()` 从**原生发射起点**（`GetFireLocationAndDirection` / `BPGetProjectileSpawnTransform`）沿武器碰撞通道验证命中所选部位；失败暂停修正但保留目标身份。
4. `OverrideWeaponAim()` 在 `hkAdjustedAim` 中改写方向（不改镜头）；`bAimRemoveSpread` 只对有效锁定清零散布；霰弹枪独立集中；泰克手枪按住左键保持目标（`PistolHold`）。

### 12.2 泰克长矛（internal/Hack/TekSpear.cpp + TekSpearRules.h）

- 选取：复用 `AimCircle` 与头/身点，按实际距离取最近 1–5 个有效敌方单位（友方/类型筛选同瞄准逻辑，另有 `bSpearAimPlayers/Creatures/Bosses` 开关）。
- 时机：读取动画近战打击标记（`HitMarkers`，含蒙太奇序列时间换算）或原生伤害窗口边沿；每个目标独立记录打击历史（`StrikeHistory`），按先后短按右键（`SimulateInputKey`）。
- 飞行物偏转：扫描 `AShooterProjectile`，以发射者判友方，按相对速度/重力/碰撞/爆炸半径预测接近时间，遮挡暂停。
- 自动正对攻击者（`FaceAttacker`/`Turn`）并在结束/暂停/换武器/卸载时回正。

## 15. 线程与安全约定（重要）

1. **UE 游戏线程回调**：ActorTick、UpdateCamera、PostRender、PhysicsRotation、ProcessEvent 链均在游戏线程串行执行；功能实现假定单线程访问游戏对象。
2. **渲染线程/绘制**：ImGui 帧与 Shadow DrawList 在 D3D12 Present 路径执行；`DrawImGui.cpp` 与 ESP 只读由游戏线程发布的数据（状态经互斥锁快照）。
3. **初始化线程 / 卸载 worker**：`dllmain.cpp` 的 `MainThread` 负责初始化；`UnloadWorker` 不直接碰 UObject，状态恢复放在游戏线程回调中完成（`PrepareRuntimeForUnload`）。
4. **对象生命周期**：
   - `IsUsableObject()`：Class 非空、非默认对象、无 BeginDestroyed/FinishDestroyed/MirroredGarbage 标志；
   - `TryGetLiveObjectSerial()` / `Weak()` / `Live()`：`FUObjectItem` 的序列号位于条目偏移 `0x10`（ASA 已验证的 0x18 字节条目布局），缓存对象必须「指针 + 索引 + 序列号」三合一校验，防止对象槽位被复用；
   - 跨帧缓存一律存 `(ObjectIndex, Serial)` 键（如 `ObjectKey()`）。
5. **状态互斥**：状态字符串用 `StatusMutex`/`ExtensionStatusMutex` 保护，渲染侧通过 `TranslateCopy` 取副本。
6. **暂停语义**：菜单打开、聊天、背包、失焦、骑乘、切图、死亡都会暂停自动化并（按功能）恢复现场；`IsViewingInventoryUI`、`g_MDX12::g_MenuState::g_isOpen`、前台进程 ID 是通用条件。
7. **卸载**：卸载前关闭会改游戏状态的功能并调用其恢复函数，否则拒绝卸载（见 §4）。

## 16. 游戏更新适配标准流程

本章是 ASA Steam 客户端每次更新后的必走流程。原则是先记录版本、再只读定位和交叉验证、最后构建与注入；任何核心地址都不得按旧、新版本的固定差值直接猜测。历史兼容记录写入 `README.md`。

### 16.1 建立版本基线

1. 完整退出已注入的旧游戏进程，确认任务管理器中没有 `ArkAscended.exe`；磁盘上的 DLL 被替换后，旧进程不会自动加载新文件。
2. 从 Steam `appmanifest_2399830.acf` 记录 `buildid`，并记录 `ArkAscended.exe` 的修改时间、文件大小和 SHA-256。
3. 从可执行文件的 `++ARK1+Rel-*` 字符串记录 CL；启动到主菜单后记录窗口显示的游戏版本。版本记录至少包含：游戏版本、CL、Steam build、EXE SHA-256 和适配日期。
4. 先检查工作区状态，保留现有未提交改动；更新只修改本次适配涉及的文件。

### 16.2 重新定位六个基础地址

目标文件为 `src/external/CppSDK/SDK/Basic.hpp`。先做静态语义定位，再用运行中客户端做外部只读验证：

| 地址 | 定位与验收方法 |
| --- | --- |
| `AppendString` | 找到读取 FNameEntry 头、以 `Header >> 6` 得到长度、区分 ANSI/UTF-16，并最终调用 `FString` 追加/赋值逻辑的外层函数；不能误选只接收裸字符缓冲区的相邻转换 helper。必须按 `FName::GetRawString(NameEntry, FString&)` 的实际调用约定复核两个参数。 |
| `GetNameEntry` | 找到按 block/index 解析名字条目的函数；由其 RIP 相对引用反推 `GNames`。 |
| `GNames` | 运行时读取 name pool，必须满足 chunk 结构可读且 `name(0) == "None"`。 |
| `GWorld` | 由简单 getter 或稳定引用定位；运行时必须得到有效 `UWorld`，主菜单通常为对象 `MainMenu`、类 `World`。 |
| `ProcessEvent` | 按 UObject 校验、UFunction flags/params 处理等语义定位；再与有效 UObject 虚表槽 `0x50` 的目标交叉验证。 |
| `GObjects` | 扫描并验证 `FChunkedFixedUObjectArray`：对象表指针、`NumElements/MaxElements`、chunk 数和每项 24 字节布局都必须合理；抽查对象索引与名称。**禁止仅按版本间 RVA 差值推算。** |

运行时验收必须同时满足：候选唯一、`GObjects` 数量在合理范围、`name(0)` 为 `None`、`GWorld` 类型正确、至少一个对象的 `ProcessEvent` 槽指向新入口。任一项失败就停止，不进行注入。

### 16.3 判断是否需要重导 SDK

地址变化不等于布局变化。先用运行时反射抽查项目高风险类型的 `UClass::Size` 和关键属性偏移，至少覆盖 `Actor`、`World`、`Engine`、`GameViewportClient`、`NetConnection`、`MovementComponent`、`ShooterPlayerCameraManager`，并与 `Assertions.inl` / 生成头文件比较：

- 大小和关键字段均一致：保留现有 SDK，只更新基础地址、入口记录和兼容说明。
- 任一核心类大小、继承、字段偏移或函数参数发生变化：用 Dumper-7 对当前客户端完整重导，合并生成的 `SDK` 与 `Assertions.inl`，再修复编译错误和手工布局。
- DLC / 模组蓝图只在相应地图或资产实际加载后按需 dump 和合并，不能用主菜单缺失的类型覆盖已有 SDK。

手工维护的高风险布局还要单独复查：`UNetConnection` 的 `RemoteIPList/RemotePort`、`UGameViewportClient` 的 `EngineShowFlags`，以及代码中带 CL/RVA 注释的原生字段。

### 16.4 核验特征码、虚表和语义守卫

1. 对 `CheatData::Signature` 中所有仍在使用的 AOB 扫描整个当前 EXE；每条必须且只能命中一次。当前必查项为 `AActor::Tick`、`UNetConnection::HandleDisconnect`、`UMovementComponent::PhysicsRotation`、`UConsole::OutputTextLine`。不用的入口保持 `"OUTDATED"`，不能为了“有结果”恢复旧特征码。
2. 在 `src/internal/CheatData/CheatData.hpp` 更新命中 RVA、日期和 Steam build 注释。AOB 是实际解析依据时，历史虚表槽只作为辅助线索，不能替代唯一命中校验。
3. 复核直接使用的槽位：`ProcessEvent=0x50`、`AShooterPlayerCameraManager::UpdateCamera=472`、`UConsole::OutputTextLine=99`、`UGameViewportClient::PostRender=122`。若槽位或目标变化，必须按函数语义确认，不能只看相邻函数位置。
4. 对 `hooks.cpp` 中的入口语义守卫重新喂入新函数头部。例如 `IsExpectedUpdateCameraAddress` 除虚表槽外还校验寄存器保存形状、CameraOwner 读取和 DeltaTime 保存；新版本字节不匹配时应更新守卫或让功能关闭，不能绕过校验。

### 16.5 修改、构建和验收顺序

按以下顺序提交一次适配：

1. 更新 `Basic.hpp` 六个地址及版本/SHA 注释。
2. 更新 `CheatData.hpp` 的 AOB、槽位和新 RVA 注释；同步更新其他带旧 CL 的有效语义守卫注释。
3. 在 `README.md` 写明版本标识、六个地址、在用 AOB 的命中 RVA、槽位结果、SDK 是否重导及验证状态。
4. 执行相关离线回归，再运行 `./build-release.ps1 -Rebuild`；必须通过 Release x64 DLL、启动器、`phoenix.exe --check`、发行目录和压缩包哈希生成。
5. 完整退出游戏并确认旧进程消失，替换 DLL；启动到主菜单后先做一次注入烟测，观察不少于 30 秒，确认菜单、PostRender、Tick、相机和日志正常且无崩溃。
6. 主菜单稳定后再进入单机/测试服务器，逐项验证依赖 World、Controller、NetConnection 和原生入口的功能；不要把“能注入”当作适配完成。
7. 只读采样、反汇编和烟测记录放入 `release/diagnostics/`；临时 dump 不进入发行包。

### 16.6 完成标准（Definition of Done）

- 六个基础地址都有静态语义依据和运行时交叉验证，`GObjects`/`GNames`/`GWorld` 不靠差值猜测。
- 所有在用 AOB 唯一命中；虚表槽和语义守卫通过，失败路径保持关闭而不是继续调用未知地址。
- SDK 布局已抽样证明未漂移，或已完整重导并通过 `Assertions.inl`。
- Release 构建、启动器 `--check`、主菜单注入烟测通过；需要进服的功能另有明确实测记录。
- `Basic.hpp`、`CheatData.hpp`、`README.md` 和本章记录一致。

启动器允许先于游戏运行，但 DLL 初始化线程在 `GWorld` 尚未发布时不得调用 `UEngine::GetEngine()`、`StaticClass()`、`FindObject*()` 或任何会遍历 `GObjects` / 解析 `FName` 的接口。游戏启动早期对象数组可能已经有数量，但条目和名字池仍未全部初始化；此时过早扫描会表现为“注入成功后立刻闪退”。入口等待逻辑位于 `src/dllmain.cpp::init`，每次更新后都要用“先开启动器、再开游戏”的顺序做一次早注入回归。

## 17. 新增一个功能的标准流程（Checklist）

以「自动换甲的部位筛选」（2026 年新增）为例，说明一条完整链路：

1. **确认游戏接口**：在 `external/CppSDK` 找到可用对象/函数（`UPrimalInventoryComponent::EquippedItems`、`AShooterPlayerController::ServerEquipPawnItem`、`UPrimalItem::MyEquipmentType/bIsItemSkin/ItemDurability`）。
2. **配置**：`Configs.h` 加 `inline bool bXXX = false;`（默认关闭）→ `ConfigManager.cpp` 保存/加载各加一行 → 必要时加旧值迁移。
3. **实现**：在 `Hack.cpp` 或新域级 `.inl` 写 handler（状态机 + 冷却 + 每帧一次动作 + `IsUsableObject` 防御 + 状态字符串 getter）；`Hack.h` 声明。
4. **调度**：接入 `AActor/Tick.cpp`（按开关调用）或对应钩子回调；关闭时也要调用以恢复现场。
5. **卸载/停止**：会改游戏状态 → 加入 `PrepareRuntimeForUnload()`；自动化开关 → 加入 `FeatureShortcuts.h::StopAll()`。
6. **菜单**：`FeatureCatalog.h::Features[]` 注册导航条目（含摘要与悬停说明）；在对应 `XXX_Menu.cpp` 的 `IsTopic(...)` 块里加控件（`DrawCustomCheckbox/Slider` + `ParameterFade` + `HelpText` + 状态行）；接口未就绪时用 `g_Hook::*OK` 禁用。
7. **语言**：新文本进 `InterfaceText.inc`，算 FNV-1a 键并同步 `language/CN.ini`、`language/EN.ini`。
8. **测试**：逻辑可离线化时在 `tests/` 加独立 `.cpp` + `run-*.ps1`；跑 `tests/language_package_integrity.py`。
9. **构建验证**：MSBuild Release/x64 编译通过；再 `./build-release.ps1` 打包；游戏内烟测。

## 18. 功能开发与逆向研究方法

> 本章总结本项目在「功能清单 → 实现 → 实机验证」迭代中沉淀的研究方法、诊断工具与经典陷阱。
> 原则只有一条：**所有结论以游戏运行时采样为准，不以函数名、字段名或本地表现为准。**

### 18.1 五条研究铁律

1. **函数名 ≠ 行为**：`ShooterPlayerController.SetGodMode(bool)` 与 `ShooterCheatManager.SetGodMode` 都只切换无敌标志，不含飞行；GCM 双击飞行实际走 `Buff_CreativeModeHelper_C → ServerSetFlight`。调用前必须反汇编/字节码核实。
2. **客户端生效 ≠ 服务器生效**：泰克步枪把本地热量清零后，若服务器仍进入过热，就没有伤害。热量、射速、冷却、耐久等服务器权威数值必须以服务器侧采样为准。
3. **只读采样优先于猜测**：先读运行时字段/函数/字节码，再动手改代码；`release/diagnostics/` 下所有脚本都是只读 RPM，绝不写游戏内存。
4. **双端对照**：客户端进程与服务器进程同时采样对比，才能区分「本地显示问题」与「服务器拒绝」。
5. **每轮只改一层、逐级缩小失败点**：自由相机从「无法开启」到「能飞但立即退出」到「能飞不能动」到「视角被重置」，每轮按采样定位到下一层失败点再修。

### 18.2 本地测试环境（标准做法）

- **建服**：`release/diagnostics/start-feature-server.ps1` 在 `E:\asa-localserver` 用 junction + hardlink 建立独立测试根 `PhoenixFeatureTest-<日期>`（共享二进制、独立存档/配置），启动 `ArkAscendedServer.exe`：`TheIsland_WP?listen`、游戏端口 7797、RCON 27097、`-NoBattlEye`、**无加入密码**；`session.json` 记录 PID。
- **进服**：游戏控制台 `open 127.0.0.1:7797`；管理员：`enablecheats <ServerAdminPassword>`（密码在测试根的 `GameUserSettings.ini`）。
- **发装备/控制**：`release/diagnostics/feature_rcon.py`（`ListPlayers`、`DoExit`、`GiveItemToPlayer <ID> "<物品蓝图路径>" <数量>`、`GiveTekEngramsTo <ID> Tek/TekRifle/TekSniper/...`）。注意物品路径以游戏内为准（如泰克狙击枪在 `/Game/Aberration/WeaponTekSniper/PrimalItem_TekSniper`，不在主目录）。

| 自由相机（本地视角） | 人物位置不变、ViewTarget 保持为相机、WASD/鼠标持续改变相机位置与朝向 |

### 18.5 逆向研究的标准顺序（从「问题」到「修复」）

1. **反射快照**定位涉及的类、字段、函数（`inspect_feature_runtime.py`，客户端+服务器各一份）；
2. **蓝图字节码**找调用路径与属性引用（`blueprint_property_refs.py` / `feature_bytecode_refs.py`）；
3. **原生反汇编**找判定分支与前置条件（`read_native_routes.py` 沿 wrapper → 实现逐层看）；
4. **双端采样**确认失败点落在客户端还是服务器（`monitor_feature_runtime.py` 前后对比）；
5. 修改实现 → 离线回归（`tests/`）→ 打包（`build-release.ps1`）→ 再采样验证，闭环迭代。

### 18.6 已验证的经典陷阱（前车之鉴）

- **反向门逻辑**：坐骑的 `bAllowUseWhileRidingDino` 在原生判断里是「开了反而退出骑手枪械输入分支」；`bForceTPV_EquippedWhileRiding` 才是持枪第三人称的强制条件。读反汇编前别按字段名字面义改。
- **客户端改模板 ≠ 服务器状态**：翼龙/南方巨兽龙服务器侧 `AllowMountedWeaponry` 为关闭时，只改客户端模板无效；两侧设置不一致必须对照确认。
- **默认对象（CDO）会被误判为无效对象**：用 `IsUsableObject` 之类检查过滤了引擎静态函数依赖的 CDO，导致调用从未执行（自由相机首版失败原因）。CDO 检查要单独放行。
- **复制标志必须在创建前清除**：`BeginDeferredActorSpawnFromClass` 会拒绝默认开启网络复制的角色，「创建后再关复制」来不及；应在创建前临时改模板、调用后立即恢复。
- **视角目标会被游戏重置**：原生相机更新会把普通 Character 的 ViewTarget 切回玩家；只有 `CameraActor` 能被接受为持久视角目标。退出时必须清理临时控制器并恢复 `AutoManageActiveCameraTarget`。
- **函数布局必须运行时核验**：调用原生/蓝图函数前用合约脚本校验参数布局与地址（`local_flight_contracts.py`、`inspect_native_entry.py`），游戏更新后不能假定不变。
- **服务器权威数值**：热量/冷却/射速/耐久等由服务器维护，客户端修改只影响表现层；判定是否「真正生效」永远看服务器扣弹、掉血与状态同步。
- **物品/技能的实际类名以运行时为准**：仙人掌汤的物品类名是 `PrimalItemConsumable_CactusBuffSoup_C`（不是 Soup_CactusBroth），buff 是 `Buff_CactusSoup_C`；凭命名习惯写令牌会漏检，必须用 §18.3 的探针实机核对后再写匹配规则。
- **未加载的蓝图内容无法反编译**：DLC/模组技能（如 Lost Colony 的幻雾脱逃类技能）只在对应地图或内容加载后才会出现在 GObjects 里；客户端快照里只有技能框架类（`PrimalBuff_Skill`、`PrimalItem_HotbarSkill_Base_C`），看不到具体技能字节码。要研究某技能，先让其内容加载（进对应地图/激活技能）再采样。
- **「免举起」等表现层优化可走物品位段**：装备动画由物品的 `bSkipEquipAnimation` 位段控制，投掷动作本身走武器原生 RPC；只改动画位段、不改服务器路径，即可实现「秒装备→立即投掷」而不破坏服务器校验。
- **手雷输入入口需区分 thunk 与原生虚函数**：2026-09-21 泰克手雷实测总开关开启仍需松键；仅安装 `ShooterWeapon.StartFire` thunk 不能证明拦截实际输入。当前客户端 thunk 调用虚表字节槽 `0xf78`，`PrimalWeaponGrenade` 在该槽有独立实现。修复改为对手雷原生入口校验前缀后安装钩子，先原生 StartFire，再在本地当前武器进入 cooking 状态后立即调用原生 StopFire，保留原生校验与服务器通知。用 `InstantThrowGrenadeCalls` / `InstantThrowGrenadeReleases` 核对命中；出弹延迟及松键不重复出弹仍须新版实测，不能仅凭安装成功宣称有效。
- **装备请求“发出但无效”的排查与自愈**：客户端把 `ServerEquipPawnItem` 发出后服务器可能静默拒绝（本地耐久/位置视图滞后、备件已损坏、或槽位只剩皮肤阻挡）。自愈策略：同一备件连续失败 ≥3 次 → 拉黑该备件 60 秒、调用 `Inv->ServerRequestItems(PC,true,false)` 强制同步一次背包、改试其它备件；只剩皮肤的槽位先用 `ServerRemovePawnItem` 摘皮、设待补穿标记再补穿。状态栏要如实报告“服务器未接受”而不是一直显示“已请求”。
- **结盟判定不要在客户端自作聪明**：`IsAlliedWithOtherTeam` 是服务器部落数据的查询；客户端（尤其单机/无部落数据时）可能对任意队伍返回 true，导致「所有非野生单位都成了友方」——自瞄/招架全部锁不住。友方判定以 `IsPrimalCharFriendly` + `TargetingTeam` 相等 + 部落名回退为准即可；新增判定前必须先在目标环境实测。
- **IsBossDino() 不可靠，按类名特征判 Boss**：`IsBossDino` 的 vtable 槽位在 BP 恐龙 CDO 上实际返回 float，按 bool 包装读取得到垃圾值。Boss 判定改用类名特征（`Dragon_` 前缀 + 蜘蛛/大猩猩/蝎狮/监察者/君王泰坦/渡渡霸王龙/泰坦 kaiju/莫德尔标记，见 `TekSpearRules.h::IsBossClassName`）；驯养生物即使带额外等级也走「生物」开关，避免关掉 Boss 开关后所有驯养龙都无法锁定。
- **候选筛选要与自动瞄准共用同一套规则**：泰克矛招架候选曾额外要求 `RootComponent` 且 `!bIsSleeping`，在单机环境把全部角色拒之门外（状态恒为「通过筛选 0」）。现在 `TekSpear.cpp::TargetEligible` 与 `Aimbot::GetBestTarget` 保持同构：有效性 → 隐藏/存活/网格 → 距离 → 类型开关 → 部落排除，禁止再往这条链上私自加条件。

### 18.7 功能开发全流程（功能清单 → 交付）

1. **清单对照**：拿到功能清单后逐项核对现有实现，产出「已实现 / 仅本地主机 / 未实现 / 待实测」对照表（模式见 `docs/phoenix-20260917-功能补充.md`），未实现项明确标注，不夸大。
2. **实现**：逐项按 §17 Checklist 走（SDK 接口确认 → 配置 → 实现 → 调度 → 卸载/停止登记 → 菜单 → 语言 → 离线测试）。
3. **离线回归 + 打包**：对应 `tests/run-*.ps1` 全绿 + `build-release.ps1` 出包。
4. **实机验证**：本地测试服 + §18.4 双端判据；结果**回写**对照表与 `README.md`（哪些已由实机确认、哪些仍待验证）。
5. **迭代**：未通过项按 §18.5 顺序定位修复，每轮重新打包、重新采样，直到判据满足或确证为服务器不可行（并把限制写进菜单帮助文本与文档）。
6. **文本/文档同步**：新界面文本用 `release/native-features/update-text.py`（及 followup/gcm-text 等变体）同步进 `InterfaceText.inc` 与 `language/*.ini`；`tests/language_package_integrity.py` 把关。

### 18.8 恐龙战队机甲光束计时实验（2026-09-24）

- 客户端 `Hack/MekBeamTiming.inl` 只在本地主机权威机甲上生效；`server/MekBeamTiming` 是已撤回部署的专服实验源码。两端实验逻辑均核对 `IsUsingZordSkin`，并只选择 `ProjDinozordMEKLaserBeam_C`／`MEKLaserBeamAttackStateRanged_C` 对应的攻击槽，关闭或卸载时恢复原值。
- 实验配置为攻击间隔 `0.5 s`、热量开始恢复的等待 `4 s`。专服实射采样确认后者约为 `3.98–4.05 s`；攻击槽虽为 `0.5 s`，连续完整光束仍约 `3.2 s` 一次，不能把攻击槽间隔当成光束内部伤害频率。
- 2026-09-24 首次专服版本因把 AsaApi 反射包装 `FDinoAttackInfo` 当作普通定长数组元素索引而崩溃。修复版按运行时 `DinoAttackInfo` 结构大小计算元素地址；首次崩溃栈已通过 `release/diagnostics/symbolize_mek_crash.py` 定位。后续确认伤害重复命中受光束蓝图 `ClearTargets` 的 `0.1 s` 定时器控制；`0.05 s` 候选只完成编译与字节码签名校验，未部署验证。用户要求只保留客户端后，现有专服插件已撤回，远程专服恢复原生参数。

### 18.9 恐爪龙自动跳跃与抓附脱离追踪（2026-09-26）

新增默认关闭的 `bDeinoAutoJumpTest` 和 `bDeinoLatchTrace`。前者在当前骑乘恐爪龙 Falling、无抓附且缓存空闲时，以 F6 按下沿调用已核验的 `ServerRequestLatchedAutoJump`，3 秒冷却，水平 5–30 m/s、向上 0–10 m/s，默认 15/4。它不追加本地运动写入。后者配合原无目标抓附，标记本功能的进入、续抓、主动取消与旧空格回退，并复用现有 ProcessEvent Hook 只读观察相关事件。

共用记录器支持互斥模式、50 ms 采样、120 秒上限、菜单/失焦/下骑停止以及日志失败时不发请求。Hook 只进行指针比较和有界参数复制，游戏线程负责名称解析和落盘；未经过该 Hook 的蓝图内部调用不可据此排除。服务器侧为独立只读采样，核对 UObject 索引、序号和类，记录缓存/抓附状态/重力/速度/位置，不装插件或写服务器运行时。

实现：`Hack/DeinoActionRules.h`、`DeinoActionTrace.inl`、`DeinoGlideProbe.inl`；规则、配置保存及停止由 `tests/feature_expansion.cpp` 验证。完整用户操作和双端判据见 [实验说明](恐爪龙自动跳跃与抓附追踪实验-20260926.md)。此前 A/B/C 滑翔基线已完成；本版自动跳跃是否被服务器接受、抓附自动脱离的实际触发来源仍待用户实测，不把编译通过当作游戏效果成立。

## 19. 常见约定与 FAQ

- **为什么远程服务器上部分修改无效？** 射速、热量、耐久等由服务器维护的数值，客户端只改本地视图；服务器仍按自身计时/校验结算。这类限制必须写进菜单帮助文本。
- **为什么新增开关要在菜单里默认关？** 项目约定所有会改变行为的选项默认关闭，避免旧用户升级后行为突变。
- **状态字符串放哪？** 功能实现文件内的静态 `std::string + std::mutex`，getter 返回 `TranslateCopy` 副本。
- **能否直接调用有副作用的 BP？** 不行。只调用原生/已核验的入口；会开火、造成伤害、消耗物品的蓝图不得在探测/显示路径调用。
- **怎样调试？** `logs/phoenix_dll_*.log`（初始化/卸载生命周期）、`OutputDebugString`、屏内 `g_LogManager::AddLog`、菜单内各功能状态行、`tests/` 离线断言。


## 界面层级与控件说明（2026-10-02）
