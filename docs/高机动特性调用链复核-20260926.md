# 高机动护甲特性调用链复核

日期：2026-09-26。核对用户所说“任何效果无法使你的移动速度降低为 60%”对应的原生路径，并判断它与超重移动的关系。依据《开发文档》§18，对客户端和隔离测试服做只读反射，对测试服做同 SHA 符号缓存反汇编；没有写入游戏进程或修改功能代码。

## 特性实体与数值

隔离测试服已加载 Wasteland 物品资产 `PrimalItem_ItemTrait_Armor_Mobile[_Moderate/_Lesser]_C` 和对应特性对象 `PrimalItemTrait_Armor_Mobile[_Moderate/_Lesser]_C`。物品 CDO 的 `MyItemTrait` 指向对应特性类；三个特性 CDO 的内部 `Name` 均为 `Mobile`、`Type=Armor`。每档只有一个 `Modifiers[]` 元素，名称为 `MinSpeedClamp`，堆叠类型为 `Multiplier`：低档 0.30、中档 0.45、完整档 0.60。三个 CDO 的 `BuffsToAddWhenEquipped` 均为空，`bUseBPGetTraitModifier=false`。反射文件位于 `release/diagnostics/mobile-review-20260926/server/`；数值来自对上述 `Modifiers[]` 指针的只读内存采样，结构布局见 SDK `FItemTraitModifier`。

当前客户端快照 `release/diagnostics/mobile-review-20260926/client/` 没有加载这些具体特性类，因此没有客户端 CDO 数值对照。服务端现有对象足以确认隔离测试服的三档配置。

## 原生调用链与顺序

服务端 `APrimalCharacter::GetMaxSpeedModifier(bool)`（RVA `0x4BC8BD0`）先从 `MyCharacterStatusComponent` 调用虚表 `0x5A0`。对当前服务端状态组件 CDO，该槽位实际指向 `UPrimalCharacterStatusComponent::GetMovementSpeedModifier()`（RVA `0x5123180`）。后者读取服务端当前重量与最大重量；重量比达到 1 时，负重速度倍率趋于 0，并可归零。

角色随后将状态速度倍率与 `ExtraMaxSpeedModifier` 相乘。若结果低于 1，调用 `APrimalCharacter::GetItemTraitModifierTotal(FName("Mobile"), ..., ModifierIndex=0, bInitOutValue=true)`（RVA `0x4BC7710`）。该函数遍历角色装备物品，转到 `UPrimalItem::GetItemTraitModifier` 读取真实物品特性，合并 `MinSpeedClamp` 值。成功后，`GetMaxSpeedModifier` 在 `0x4BC8CBB` 用 `maxss` 取“原倍率”和“特性结果”的较大者。即在这个阶段，真实完整档 `Mobile` 能把低于 0.60 的倍率抬到 0.60。之后仍有组件自定义数据倍率、角色禁速位等计算；`AShooterCharacter::GetMaxSpeedModifier` 也在基类返回后继续乘其他倍率。因此文案中的 60% 是此阶段的下限，不是对所有后续计算的绝对保证。

`APrimalCharacter::GetItemTraitModifierTotal` 读取角色 `MyInventoryComponent` 的装备列表，玩家还可纳入手持武器的关联物品；它不会根据客户端任意写入的 Actor 标签直接授予 `Mobile`。服务端 `AShooterGameMode::bPreventItemTraitEffects` 可全局阻止特性读取。原生反汇编与二进制来源见 `release/diagnostics/mobile-review-20260926/server-native/` 的 `APrimalCharacter.GetMaxSpeedModifier.asm.txt`、`APrimalCharacter.GetItemTraitModifierTotal.asm.txt`、`UPrimalCharacterStatusComponent.GetMovementSpeedModifier.asm.txt` 和 `provenance.json`。

## 对超重移动的判定

静态调用顺序表明，**服务端认可的真实“高机动”护甲特性可能抵消服务端负重造成的速度倍率归零**。这修正了先前仅从负重函数单独观察得出的“不可能”判断：负重函数之后确实有 `Mobile` 下限。它没有把重量清零或提高上限，而是在角色速度计算中抬高一个倍率。

这不等于客户端可伪造词条，也不等于任意坐骑能借用骑手护甲效果。远程服务器会基于自己的装备物品与特性重新计算。当前没有“服务端重量超过上限、真实高机动已装备、持续行走且无位置纠正”的双端实测；也没有证明任意坐骑能装备并消费该 Armor 特性。故本轮可以确认**服务端代码具备该速度下限路径**，不能把“任意人物／龙在任意服务器超重正常移动”标为已实现。

下一步验收应在隔离服分别测试：无特性超重人物、服务器授予完整档高机动的超重人物、骑手超重与坐骑自身超重。每组同时记录两端装备 `Mobile`、当前／最大重量、状态速度倍率、最终 `GetMaxSpeedModifier`、位移和服务器纠正。测试完成后再决定是否与目标相符。
