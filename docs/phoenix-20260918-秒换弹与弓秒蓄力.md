## 2. 功能语义

### 2.1 秒换弹 `bInstantReload`

对命中的武器类型执行三件事，**扣弹、冷却、伤害、命中全部保留原生流程**：

1. **换弹时长字段归零**：把 `WeaponConfig`（`FWeaponData`）内
   `ReloadDurationPerAmmoCount`（逐发装填，霰弹枪逐发上膛）与 `NoAnimReloadDuration`（整体换弹）置 0。
2. **弹夹维持**：本地把 `CurrentAmmoInClip` 立即补到容量，容量按 `WeaponConfig.AmmoPerClip` → 关联物品 `BPGetMaxAmmo()` → 当前值 依次解析并做 1–512 清洗。
3. **远程服务器尽力而为**：不拥有 authority 时额外按 120ms 间隔发送原生 `ServerStartReload()`，并即时补满本地弹夹视图；服务器仍按其自身换弹时长结算。

| 类型 | 说明 |
| --- | --- |
| 本地主机／单机 | 改的是服务器权威对象本身，换弹时长真正归零；`bInstantReloadProtectAmmo` 可再附加 `bDontTakeAmmoOnReload`（换弹不消耗弹药）。 |
| 远程服务器 | 只能改本地副本；服务器权威时长无法从客户端下发，实际换弹速度以服务器结算为准（菜单文案如实说明）。 |

### 2.2 弓秒蓄力 `bFastBow`

- 把当前手持弓的 `PullingTimeForMaximumSpeed`（满蓄力所需拉弓时间）压到 0.001s，因此按下左键后极短时间即为满蓄力弹速。
- 分项筛选：`bFastBowWood` / `bFastBowCompound` / `bFastBowTek`；模组弓继承原版弓类时归入木弓开关。
- 泰克弓即时命中模式（`bIsAccessoryActive`）由蓝图直接结算，不经过拉弓蓄力，已排除。
- **满蓄力直接出箭（联机尝试）** `bFastBowForceShot`：`hkStartFire` 在「补丁已生效 + 手持弓 + 本机人物」时把 `PullingTime` 写成满蓄力阈值（出箭弹速由原生公式按 `PullingTime` 计算，只压缩阈值会打出最低弹速），再直接调用原生 `BPFireWeapon()` 并吞掉原生 `StartFire`，跳过松键等待。仍走原生扣弹／冷却／命中／服务器结算，不伪造伤害。
- 旧 `bFastBow` 在 `FeatureExpansion.inl` 的 authority-only 字段补丁（原槽位 6/7）已移除以避免两套补丁争用同一字段，槽位 6/7 空出但**数组仍保留 26 项**，因为槽位 23/24/25（骑乘持枪）仍在使用。

### 2.3 泰克榴弹发射器（Genesis DLC）

该武器类 `WeapTekGrenadeLauncher_C`（物品 `PrimalItem_WeaponTekGrenadeLauncher_C`，生成路径 `/Game/Genesis/Weapons/TekGrenadeLauncher/`）**不在 `src/external/CppSDK` 内**；SDK 里只存在 `FTekGrenadeLauncherSlot { AmmoType, LastFireTime, bIsLoaded }` 结构体且无任何类引用它。因此：

- 识别：`ClassifyReloadWeapon` 按运行时类名／关联物品类名匹配 `grenadelauncher`（先于其它族判断），识别成功才进入秒换弹；所在武器族须 `bInstantReloadLauncher` 开启。
- 机制侦察（只读）：`ScanTekLauncherAmmoSlots` 以 2 秒限频遍历类链，反射列出弹药类型数组、当前槽位、槽位结构体各字段（含布尔当前值）到菜单状态区。**不写游戏内存**，用于后续实机核对多弹种、逐槽装填与引爆模式字段。
- 投掷物瞬间扔出：`IsThrowableGrenadeWeapon` 在原 `APrimalWeaponGrenade` 判断外增加 `bInstantThrowLauncher` 放行的类名识别，命中后走既有 `ServerFireProjectile` 立即投出分支。

## 4. 待实机验证项（**尚未验证，不得视为已生效**）

按 `docs/开发文档.md` §18.4 双端判据，需要本地测试服（`release/diagnostics/start-feature-server.ps1`）+ 客户端采样确认：

1. **本地主机秒换弹**：换弹时 `AmmoReloadState` 与 `CurrentAmmoInClip` 的实际变化，逐发装填（霰弹枪）是否真的零时长。
2. **远程服务器秒换弹**：观察服务器侧弹夹扣减与换弹完成时机，确认 120ms 重发原生 `ServerStartReload` 是否被服务器接受；若服务器拒绝高频请求，需要退回原生节奏并更新菜单文案。
3. **弓秒蓄力（远程）**：`PullingTimeForMaximumSpeed` 补丁只作用于本地副本，**服务器是否按自身拉弓时间重算弹速尚未验证**。判据：实际出箭间隔、箭速（`monitor_projectile_motion.py`）、目标掉血与服务器弹夹扣减。
4. **满蓄力直接出箭**：确认不会造成二次出箭（`StartFire` 被吞掉后 `StopFire` 是否仍会补发）、骑乘与瞄准状态下是否正常、无弹药时是否被原生拒绝。
5. **泰克榴弹发射器**：需要该 DLC 内容加载后用 `inspect_feature_runtime.py` 导出 `WeapTekGrenadeLauncher_C`，核对
   `bIsA(AShooterWeapon_Projectile)`、弹药槽数组真实字段名（是否即 `FTekGrenadeLauncherSlot` 的持有者）、以及 `AmmoPerClip` / `NoAnimReloadDuration` 是否可写；同时回读菜单里的弹药槽侦察文本。
6. **卸载恢复**：注入 → 开启两项功能 → 换枪 → 卸载，确认弓的 `PullingTimeForMaximumSpeed` 与武器 `WeaponConfig` 换弹字段都回到原值（`release/diagnostics/read_feature_symbols.py`）。

## 5. 已知限制

- 服务器权威数值（换弹时长、拉弓时间、热量、耐久）**无法从客户端下发给远程服务器**：秒换弹在远程服的收益限于「本地弹夹视图即时补满 + 尽早重发原生换弹请求」，弓秒蓄力在远程服的实际弹速待验证。菜单帮助文本已如实写明，未夸大为「远程可用」。
- 泰克榴弹发射器的一切判断都建立在运行时类名匹配之上；若该武器蓝图改名或使用非 `grenadelauncher` 类名，需要按 §18.5 重新采样后更新 `InstantReloadRules.h` 的匹配表。
- 满蓄力直接出箭默认关闭（`bFastBowForceShot=false`），属于实验项。
