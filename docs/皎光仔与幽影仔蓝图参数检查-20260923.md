# 皎光仔与幽影仔蓝图参数检查（2026-09-23）

## 检查方法与范围

在独立本地测试服和客户端进程中，只读检查已加载的 `Lumina_Character_BP_C`、`Umbra_Character_BP_C`、共同父类 `Eclipsar_Character_BP_C` / `Draco_Character_BP_C`，以及各自的 `BP_DracoFlightMovementComponent_C` 实例。皎光仔通过测试服 `SpawnDino` 命令加载。数值取服务端类默认对象和实际飞行组件，皎光仔关键飞行值也在客户端核对。运行时快照保存在 `release/diagnostics/dragontopia-20260923/`。

这次没有修改游戏进程内存、蓝图包或项目功能，也没有做客户端改值后的服务端行为实验。因此“存在可调字段”不等于“客户端单改就能改变联机结果”。

## 飞行与能量

两只生物的实际飞行组件数值相同：

| 字段 | 当前值 | 用途 |
| --- | ---: | --- |
| `HoverMode.MaxFlySpeed` | 1300 cm/s | 悬停飞行上限 |
| `SprintMode.MaxFlySpeed` | 4200 cm/s | 冲刺飞行上限 |
| `SprintFlightStaminaDrainPerSecond` | 50 | 冲刺飞行每秒耐力消耗 |
| `SprintFlightStaminaDrainIntervalSeconds` | 1 s | 消耗检查间隔 |
| `SprintFlightMinStaminaToEnter` | 50 | 进入冲刺飞行所需最低耐力 |
| `ManeuverStaminaCost` | 200 | 飞行机动耐力消耗 |
| `BarrelRollDashSpeed` | 5000 cm/s | 桶滚冲刺速度 |
| `BarrelRollDashDistance` | 4000 cm | 桶滚冲刺距离 |
| `DiveMaxBonusSpeed` | 2500 cm/s | 俯冲额外速度上限 |

飞行组件还公开 `GetEffectiveSprintFlightStaminaDrainPerSecond`、`GetEffectiveManeuverStaminaCost` 等计算入口，以及 `ServerTryStartManeuver`。这表明技能、Buff 或服务端可能参与最终计算，表中是组件基础值。

`DracoEnergyPercent` / `DracoEnergyDrainPerSecond=0.001` 属于“狂怒/形态”技能能量，不是冲刺飞行耐力。`DracoEnergyAddOnDamageMultplier=0.0002` 与伤害转化能量有关。两只生物均使用技能名 `UmbraLumina_DracoFury`。若用户所说“滑翔能量”是飞行时耗尽的耐力，应优先检查上表的冲刺飞行字段和生物耐力属性。

## 两者区别与修改可行性

- 幽影仔攻击表 8 项；皎光仔 9 项，新增 `ATTACK - GET ME`。皎光仔还有 `HealthPercentRequiredToGetMe=0.2`。
- 幽影仔 `SkillRedirectPlasma=Umbra_PlasmaProjectileRedirect`；皎光仔对应 `Lumina_LightProjBack`。两者瞬移投射物标签、互换目标标签与蓄力投射物类不同。
- 共同飞行、狂怒、瞬移和多数攻击基础字段在蓝图或组件上可定位，适合做可恢复、默认关闭的本地实验；客户端单改是否被服务端接受仍需实际联机测试。若要稳定改变服务器规则，应修改服务端对应资产/逻辑，并让客户端显示与之匹配。

## 零耐力联机验证

在独立测试服上，玩家骑乘幽影仔，耐力确认为 0。临时改动均使用实例指针、对象索引/序列号核对，计时结束恢复原值。

| 实验 | 结果 |
| --- | --- |
| 仅客户端将疾飞最低耐力、飞行/机动消耗和全部 8 项攻击耐力消耗设为 0；服务器保持默认值 | 仍无法切入疾飞；普通单发投射物按钮为黑色，不能发射 |
| 客户端和独立测试服同时设为 0 | 耐力为 0 时可以切入疾飞；普通单发投射物仍为黑色、不能发射 |

早期一次客户端飞行消耗 `50→5` 实验误选了未骑乘的幽影仔，观察结果无效，不用于判断客户端控制权。上述零耐力实验已锁定玩家骑乘的实例。结束后客户端和测试服飞行组件的 `SprintFlightMinStaminaToEnter`、`SprintFlightStaminaDrainPerSecond`、`ManeuverStaminaCost` 均核对恢复为 `50/50/200`。

进一步静态核对测试服 `DracoFlightMovementComponent` 原生逻辑：`ServerSetSprintMode` 最终进入服务端疾飞切换路径，后者调用的检查函数读取服务器生物耐力（`CurrentStatusValues[Stamina]`）与服务器飞行组件的 `SprintFlightMinStaminaToEnter`。因此仅把客户端门槛改成 0，不能让服务器在耐力为 0 时接受疾飞。普通单发投射物还存在独立的按钮/技能准入条件；仅改 `AttackInfos[].StaminaCost` 不足以点亮或发射，具体额外条件尚未定位。

用户后续限定只修改本地客户端。基于当前证据，零耐力疾飞和普通投射物都不能作为已验证有效的纯客户端功能交付；本地 HUD、特效、输入与预测值可以直接在客户端改，但不代表服务器承认对应战斗或运动结果。

## 纯客户端能力边界

| 修改方式 | 客户端可做的事 | 联机实际结果 |
| --- | --- | --- |
| 直接改本地对象字段/蓝图默认值、挂钩函数 | 改 HUD、提示、相机、特效、输入处理和客户端预测；也可临时改本地飞行/攻击字段 | 只有纯本地效果可直接成立；复制状态可能被服务器覆盖 |
| 调用游戏已有的服务器 RPC/请求 | 在本地构造并发送游戏支持的动作请求 | 服务端仍按自己的耐力、技能、距离和冷却等规则决定是否执行 |
| 修改服务器代码、资产或服务器运行时参数 | 改服务端准入与计算 | 超出“只改本地客户端”的要求；本次仅在独立测试服做过短时对照 |

项目现有 `phoenix` 客户端 DLL 本来就包含本地字段补丁与函数挂钩，因此“只能靠请求修改”不准确。游戏结果涉及服务器时，客户端能用的正常同步通道主要是已有请求与服务器允许的客户端输入。当前 `DragontopiaSkillTuning` 函数在源码中有飞行/技能字段补丁雏形，但要求骑乘生物具有本地 `Authority`，且暂未找到调度调用点；它不能直接当作远程服务器上的可用功能。

SDK 中 `PrimalDinoCharacter::ServerRequestAttack` 的请求参数只有攻击索引，没有伤害、耐力成本或攻击范围参数。这进一步限制了通过该正常请求改变攻击计算值的空间；普通单发投射物在零耐力的客户端实验中也未进入可发射状态。是否存在其他被服务器信任的输入必须针对具体功能单独验证，不能因本地无反作弊就推定服务器接受任意数值。

## 俯冲蓄速机制补查（2026-09-27）

用户所称“滑翔能量”在飞行组件中更准确地对应 `CurrentDiveAlpha`（0～1 的俯冲比例）与 `DiveCurrentBonusSpeed`（额外飞行速度），没有看到独立的“滑翔能量池”。当前客户端 `ArkAscended.exe`（2026-09-26 文件版本）和旧独立测试服二进制的对应计算路径均调用读取生物实际速度向下分量的函数：取速度向量 Z 分量的负值，并与 0 取较大值。计算不读取镜头俯角。

当前客户端运行时皎光仔、幽影仔飞行组件相同：`DiveMinDownSpeed=1200 cm/s`，`DiveFullDownSpeed=3000 cm/s`，`DiveMaxBonusSpeed=2500 cm/s`，`DiveSpeedRiseRate=1500`，`DiveSpeedFallRate=750`。俯冲比例的目标值约为 `clamp((向下速度-1200)/(3000-1200), 0, 1)`；实际加速值再按飞行模式和技能修正的升降速率逼近目标。向下速度不够时目标值为 0，已有加速会衰减。

飞行模式参数显示：悬停模式允许后退与横移；疾飞模式 `bOnlyForwardsInputAcceleration=1`，不允许后退/横移。达到最大俯冲时的旋转速率系数 `DiveRotationRateScaleAtMax≈0.35`，说明高速俯冲转向本身也受限制。可以在一定程度上让镜头和玩家操纵分离，但单独让镜头朝下、实际速度保持平飞不会继续蓄速。若真实向下速度一直大于阈值，恐龙会持续下降；仅靠本地伪造向下速度或加速值，联机时也未证明可改变服务器的实际运动结果。
