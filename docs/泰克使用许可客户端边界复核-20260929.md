# 泰克使用许可客户端边界复核（2026-09-29）

## 结论与问题修正

**泰克的使用检查与永久学习印痕必须分开研究。** 本地可以存在独立的菜单、装备、能力前置检查，但没有证据表明一个统一的客户端“泰克许可”开关能让全部建筑、武器和鞍具获得服务器认可。

上一轮证明的是普通客户端不能通过已核查入口无条件永久学习泰克印痕；不能仅凭该结果断言所有泰克使用动作都无法从客户端影响。本轮另外追踪了装备与使用的实际原生调用链。

当前明确的结果：已追通的默认原生装备 RPC，以及从库存取出/切换武器的使用 RPC，都会在服务器检查所需印痕。仅放开本地检查，不会自动放开服务器自己的检查。特殊建筑交互、鞍具主驾驶骑乘、乘客登乘、鞍炮开火、已经装备后的特殊能力须各自核验，不能相互代替。

## 基线和限制

- 本轮没有检测到运行中的 `ArkAscended.exe` 或 `ArkAscendedServer.exe`，没有现场行为采样。
- 复用 2026-09-28 的客户端只读反射快照；当前磁盘客户端 SHA256 仍是 `7a08ef6ea5d2050708d02dc451632ad2a245c7d689a8065b2d90c16443c3cc96`，本轮额外反汇编其装备查询与 `HasEngram`。
- 服务器静态样本 SHA256 是 `a2aee3fd6c233b26cdbd2f640c35c36962dad9acee5ef8bd83dc5df38a1422e7`，使用完全匹配该哈希的本地符号缓存。它不是当前所连远程服务器的运行时样本。
- 本轮没有改内存、改人物状态、发送 RPC、安装服务器插件或实现本地解锁开关。结论属于代码审查，未声称联机验证成功。

## 已核验的武器与装备检查

### 所需印痕是独立装备条件

`UPrimalItem.EquippingRequiresEngrams` 位于 `+0x3a0`，不是“所有泰克通用”的单个权限位。保存的客户端模板中，泰克步枪、泰克狙击枪、泰克胸甲及泰克手套各有 1 个装备印痕要求，`bAlwaysLearnedEngram` 均为 false。

SDK：`src/external/CppSDK/SDK/ShooterGame_classes.hpp:1173`；模板证据：`release/diagnostics/tek-use-research-20260929/saved-client-evidence.json`。

### 服务器并非直接信任本地装备放行

服务器静态样本的实际路径：

```text
ServerEquipPawnItem_Implementation
  → UPrimalInventoryComponent.ServerEquipItem
  → CanEquipItem
  → 物品 AllowEquipItem（虚表字节槽 0x3f8）
  → 按 EquippingRequiresEngrams 检查服务器玩家 HasEngram
```

关键原生位置：

- `ServerEquipPawnItem_Implementation`：RVA `0x4eecd50`，从服务器人物取得库存后调用 `ServerEquipItem`。
- `ServerEquipItem`：RVA `0x51f6bd0`；`0x51f6c43` 调 `CanEquipItem`，失败退出。
- `CanEquipItem`：RVA `0x51ca830`；`0x51ca98f` 调物品虚表槽 `0x3f8`，失败退出。
- `AllowEquipItem`：RVA `0x521ea20`；`0x521ee6b` 调 `HasEngram`，失败分支到 `0x521fcdf`。

`server-native/vtable-proof.json` 从该服务器样本的 `UPrimalItem` 构造函数定位虚表，确认槽 `0x3f8` 指向 `AllowEquipItem`，没有仅凭客户端包装的函数名推断目标。

服务器库存自身的 `bIgnoreEngramEquipRestrictions`（`+0x678` mask `4`）可以使上述装备实现跳过该段印痕检查。这是服务端库存规则的例外；只修改本地库存副本不能改变服务端的同一位。不同物品的蓝图覆写也需要单独确认。

武器还有独立的 `UPrimalItem.CanEquipWeapon()`：服务器样本 RVA `0x5221f60` 遍历 `EquippingRequiresEngrams`，`0x52220cb` 调玩家 `HasEngram`，失败拒绝。`UPrimalItem.Use(bool)` 的武器分支确实调用该函数，而不是仅在 UI 中显示一个提示。

本轮也追通了独立的武器网络请求链，未把护甲装备请求当作武器入口：

```text
ServerRequestInventoryUseItem_Implementation
  → UPrimalInventoryComponent.ServerUseInventoryItem
  → UPrimalItem.Use（虚表字节槽 0x430）
  → CanEquipWeapon
  → 服务器 HasEngram
  → 检查通过后才进入 StartWeaponSwitch
```

RPC 在 `0x4ef3278` 调库存使用方法，后者在 `0x51f93dc` 读取物品虚表槽 `0x430` 并于 `0x51f93f5` 调用。`weapon-use-vtable-proof.json` 将该槽精确对应到 `UPrimalItem.Use(bool)=0x5255b90`。其武器分支 `0x5256200` 调 `CanEquipWeapon`，失败退出。因此对走此原生路径、实际要求印痕的武器，普通库存取出/切换也不能仅通过修改本地许可得到服务器接受。已持有武器的特殊开火模式不包含在此结论中。

当前客户端磁盘原生代码也确认同样的查询结构：`CanEquipWeapon` 的 exec 直接调用 RVA `0x6b2b5f0`；该实现 `0x6b2b7cc` 调 `HasEngram(0x6754540)`，返回 false 则拒绝。客户端和服务器各自检查自己的状态，改变其中一端不能自动改变另一端。

### HasEngram 不只是读取显示列表

当前客户端 `HasEngram` 与服务器符号样本交叉确认：

1. 检查所查询物品 CDO 的 `bAlwaysLearnedEngram`（`+0xb50` mask `4`），为 true 则返回 true。
2. 否则查询玩家状态 `+0x1118` 的印痕查找集合；该函数没有直接遍历已复制的 `EngramItemBlueprints@0x1108` 数组。后者仍是正式的玩家印痕状态字段，服务器解锁也会更新它，并非纯 UI 数据。

这解释了为什么“改数组显示已学”“某次本地 HasEngram 返回 true”“服务器接受使用”不能等同。它也说明存在本地查询分支，不应笼统说客户端完全无法影响任何印痕判断；真正限制在于动作最后会执行哪些服务器检查。

## 仍需按对象和动作区分的项目

| 项目 | 已发现的检查线索 | 不能据此声称的结果 |
| --- | --- | --- |
| 泰克建筑 | 建筑/库存各有 `EngramRequirementClassOverride`；本地轮盘和 `ServerMultiUse` 是不同执行层 | 不能把放开轮盘当成服务器完成传送、启动或制作；也不能断言每一种建筑的每个功能都检查印痕 |
| 鞍具 | `BoardingRequiresEngram` 位于乘客座位定义 `FSaddlePassengerSeatDefinition+0x90` | 不能据乘客字段断言主驾驶骑乘或鞍炮开火采用同一规则 |
| 泰克护甲/特殊能力 | `Buff_TekArmor` 有 `AbilityRequiresEngrams`、`HasRequiredEngrams`、`CanUseTekAbility` 和 `Server_SetTekAbilityActive` | 当前没有完整相关父类字节码，不能仅凭名字断言能力检查只在本地或必定在服务器重做 |
| 已经拿在手上的武器开火 | 还有 `CanFire`、`ServerStartFire`、各类弹丸入口与蓝图实现 | 装备检查结论不等于完成所有武器的每条开火/伤害路径审查 |

建筑通用链另外确认：`ServerActorViewRemoteInventory_Implementation → ServerViewRemoteInventory → RemoteInventoryAllowViewing`，资格返回 false 时服务器退出，通过后才登记查看状态及打开容器；资格函数还会执行可选的 `BPRemoteInventoryAllowViewing`，保留其拒绝结果。`ServerMultiUse_Implementation` 也在服务器重新枚举交互条目，匹配请求索引及检查禁用位。因此放开本地轮盘或访问按钮不是实际成功证据。

但在核查的通用容器查看、切换及交互函数中，没有发现直接调用 `HasEngram`，也没有恢复具体泰克复制器/传送器的完整相关蓝图。**本轮不能证明每一种泰克建筑都检查印痕，不能证明某个特定建筑的印痕检查是否只在本地执行。** 具体证据与范围见 `buildings/findings.md`，此路径相对下面的诊断目录。

具体测试时，应记录“无对应印痕 → 某物品的某个动作”，并以服务器上的装备变化、弹丸/伤害、建筑状态或骑乘/鞍炮状态为成功判据，而不是只看按钮、动画或客户端提示。当前缺少这组现场对照，不把候选本地检查称作可用解锁功能。
