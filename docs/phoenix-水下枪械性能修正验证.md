# 水下枪械卡顿修正 · 2026-09-16

用户实机反馈上一版已能水下发射子弹，但开启后明显卡顿。本次定位到游戏线程上的整背包扫描与重复对象验证开销：每次查找已处理武器时调用完整 Get 验证，形成大量重复继承遍历、反射名称解析及 VirtualQuery 查询。

已调整：当前武器优先处理并即时响应换枪；背包每帧最多解析 4 项，后台维护最多 4 条，并设置 0.75ms 软预算。新武器首次验证不能中途打断，因此该预算不是严格帧耗时上限。一次完整背包扫描结束后间隔 500ms 再开始；大背包的首次发现会分布在多帧完成。

验证缓存仅在当前回调内生效，不缓存跨帧内存保护结果。已捕获武器使用索引、序列号、所属类、CDO 和反射字段布局核验；值未改变时不重复写入。世界时间只在首次修改默认对象时读取。背包扫描期间物品移除或重排，不会把尚未访问的默认对象误判为已离开背包。记录数量限制为 256，当前实例优先，容量驱逐保留新实例的原始值来源。

受控原生基准使用真实 SDK 布局，直接执行完整生产辅助层和开关流程；不连接游戏进程。原游戏在后台运行，因此耗时受机器负载影响，查询次数可用于确认重复工作已消除。
